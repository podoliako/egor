# Независимая прямая задача

Расчёт первых приходов для **одного типа волн** в изотропной 3-D скоростной
модели. Расчётный модуль не импортирует EMTomo, не генерирует
модель/станции/события, не добавляет шум и не запускает инверсию.
Для генерации **входов** есть отдельный блок `generator.py` в том же пакете.

Для каждого события на выходе:

```text
arrival_time_s(event, station) = T(event, station) - min_station T(event, station)
```

Первый приход всегда `0`. Это не время от момента возникновения события.
При необходимости абсолютные времена распространения доступны через
`compute_travel_times()`, но не записываются в таблицу наблюдений.

## Входной контракт

- `VelocityGrid(velocity, cell_size_m, origin_m=(0, 0, 0))`:
  - `velocity` — массив `(nx, ny, nz)`, скорости в **м/с**, все значения конечны и положительны;
  - кубические ячейки, одинаковый шаг по трём осям в **метрах**;
  - `origin_m` — нижний угол области, **не центр первой ячейки**;
  - скорость `velocity[i,j,k]` постоянна внутри соответствующего вокселя;
  - индексы соответствуют осям `x,y,z`, без географических преобразований.
- `PointSet(ids, coordinates_m)` отдельно для станций и событий:
  - координаты — массив `(N,3)` в метрах, в той же системе, что и модель;
  - ID — уникальные строки или целые числа, нормализуются в строки;
  - строковые ID вроде `"001"` сохраняются, `1` и `"1"` считаются дубликатами;
  - массивы непустые; разные ID могут иметь одинаковые координаты.
- Закрытая область модели: `origin <= xyz <= origin + shape * cell_size_m`.
  Станции на поверхности допустимы. Точки за пределами модели отклоняются,
  а не переносятся на границу. Координаты не округляются до сетки.

## Python API

Из корня репозитория:

```python
from projects.forward_modeling import (
    VelocityGrid, PointSet, ForwardConfig,
    compute_arrivals, save_inputs, run_experiment, load_inputs, load_arrivals,
)

# Эти массивы передаёт вызывающая сторона либо отдельный генератор геометрии.
model = VelocityGrid(velocity, cell_size_m=100.0, origin_m=(0, 0, 0))
stations = PointSet(station_ids, station_xyz_m)
events = PointSet(event_ids, event_xyz_m)

arrivals = compute_arrivals(
    model, stations, events, config=ForwardConfig(refinement=4),
)
# list[Arrival(station_id, event_id, arrival_time_s)]
# Порядок: события во входном порядке, внутри каждого — станции во входном порядке.
```

Сохранение и воспроизводимый запуск:

```python
root = "projects/forward_modeling/experiments"
save_inputs(root, "true_model_001", model, stations, events)
run_experiment(
    root, "true_model_001",
    config=ForwardConfig(refinement=4),
    max_difference_s=0.001,  # пример порога: 1 мс, НЕ универсальная рекомендация
)
```

Если расчёты с `refinement=4` и `8` расходятся больше порога, вызов выдаст
ошибку и не опубликует output. Можно повторить расчёт с большим `refinement`.
Автоматического неограниченного сгущения нет: в 3-D оно быстро расходует память.

## Запуск из командной строки

Установка зависимостей:

```sh
python -m pip install -r requirements.txt
```

Новая вычислительная зависимость — `pykonal==0.4.1` (Cython/C++; при отсутствии
готового wheel установка требует компилятора). `ttcrpy` модулем не используется.

Сгенерировать входы примера и затем отдельно рассчитать времена:

```sh
python -m projects.forward_modeling.generator checkerboard_240x120x120_98st_1000ev_seed42
python -m projects.forward_modeling checkerboard_240x120x120_98st_1000ev_seed42 --refinement 32
```

Обе команды откажутся перезаписывать существующие эксперимент/результаты.
CLI генератора принимает `--lengths-km X Y Z`, `--blocks NX NY NZ`,
`--velocities-m-s V1 V2`, `--surface-stations NX NY`, `--events N`,
`--event-grid-shape NX NY NZ`, `--min-depth-km Z`, `--bottom-bias B`,
`--seed N` и `--root PATH`. Без `--event-grid-shape` события создаются по
scrambled Sobol, как прежде. С `--event-grid-shape` число событий равно
`NX×NY×NZ` (если указан `--events`, он должен совпадать). Гипоцентры лежат
на собственной трёхмерной сетке центров равных интервалов X/Y/Z; она не
привязана к ячейкам скорости или к FMM. `--bottom-bias` слегка сдвигает
уровни Z к дну, сохраняя структурированное декартово произведение координат.
`--seed` в таком режиме не меняет координаты сетки, но можно передать его
отдельно как seed шума решателя. Количество блоков и длины должны определять
**кубические** скоростные ячейки.
Доступен Python API `generate_checkerboard(CheckerboardConfig(...))` для генерации
без записи файлов и `save_checkerboard(root, id, config)` для их сохранения.

После подготовки входных файлов можно запустить и другие конфигурации решателя:

```sh
python -m projects.forward_modeling true_model_001 --refinement 4 --check-convergence
```

С обязательным порогом сходимости:

```sh
python -m projects.forward_modeling true_model_001 --refinement 4 --max-difference-s 0.001
```

`--root /path/to/experiments` меняет корневую папку. По умолчанию используется
папка `experiments` рядом с этим README. CLI **решателя** ничего не генерирует —
читает существующий `input/EXPERIMENT_ID`. Имена экспериментов: ASCII-буква/цифра
в начале, далее буквы/цифры, `_`, `-`, `.`.

## Шум наблюдений

Шум включается явно флагом `--noise`; без него расчёт остаётся чистым.
Он отделён от FMM и задаётся через `NoiseConfig` / отдельный модуль `noise.py`:

```text
T_noisy[e,s] = T[e,s] + α · T[e,s] · Z1[e,s] + σ_pick · Z2[e,s]
arrival[e,s] = T_noisy[e,s] − min_s(T_noisy[e,s])
```

`T` — **абсолютное время распространения**, а не время относительно первой
станции. `Z1`, `Z2` — независимые стандартные нормальные случайные величины,
также независимые для разных пар событие–станция. Первая составляющая растёт
с временем пробега (прокси длины трассы); вторая не зависит от расстояния.
При включении шума значения по умолчанию:

- `--noise-relative-sigma 0.01`: 1% абсолютного времени пробега;
- `--noise-absolute-sigma-s 0.05`: постоянная ошибка пикирования **50 мс** —
  начальное настраиваемое значение, а не оценка реального прибора;
- `--noise-seed 42`: воспроизводимая реализация.

Суммарная σ до нормировки: `sqrt((0.01*T)^2 + 0.05^2)` секунд.
После вычитания минимального **зашумлённого** прихода первый приход снова равен
нулю, а остальные неотрицательны; первой может стать другая станция.
Ошибки относительных времён после этой операции уже не независимы и не обязаны
иметь нулевое среднее. Отрицательные абсолютные пики, возможные в гауссовской
модели, не обрезаются до нормировки, чтобы не вносить дополнительное смещение.
Это ошибки измерения времени, а не отрицательные физические времена пробега.

Каждая пара имеет отдельный PCG64-поток, ключ которого получен SHA-256 из seed и
ID события/станции. Перестановка или выбор подмножества входов не меняет шум
сохранившихся пар **до относительной нормировки**. Удаление станции может
изменить минимум события и, следовательно, все его относительные времена.
Нулевая σ отключает соответствующую составляющую. Параметры и версии алгоритма
и NumPy записываются в `output/<ID>/metadata.json` в раздел `noise`.

**Новый шумовой вариант — новый ID**, исходные данные не перезаписываются.
Например, из корня проекта скопировать точные входы существующего примера:

```sh
cp -R projects/forward_modeling/experiments/input/checkerboard_240x120x120_98st_1000ev_seed42 \
  projects/forward_modeling/experiments/input/checkerboard_240_noise01_pick005_seed42
python -m projects.forward_modeling checkerboard_240_noise01_pick005_seed42 \
  --refinement 32 --noise --noise-relative-sigma 0.01 \
  --noise-absolute-sigma-s 0.05 --noise-seed 42
```

Команда копирования предназначена для ещё не существующего нового ID.
Из одних сохранённых **относительных** приходов нельзя восстановить абсолютные
времена для корректного шума `α*T`; пример выше заново решает прямую задачу.
Для повторных реализаций без FMM в Python можно сохранить результат
`compute_travel_times()` и применять `add_arrival_noise(times, events.ids,
stations.ids, NoiseConfig(...))`, затем вычитать минимум по станциям.
`compute_arrivals(..., noise=NoiseConfig(...))` и
`run_experiment(..., noise=NoiseConfig(...))` делают это автоматически.

`compute_travel_times()` и `check_convergence()` всегда **без шума**:
стохастические ошибки наблюдений не участвуют в проверке численной сходимости.
Шум не заменяет проверку точности прямой задачи и сам по себе не устраняет
inversion crime.

## Файлы эксперимента

```text
experiments/
  input/
    true_model_001/
      model.npz
      stations.csv
      events.csv
      generation.json     # только для входов, созданных генератором
  output/
    true_model_001/
      arrivals.csv
      metadata.json
```

**Входы / истинные параметры:**

- `model.npz`: `velocity` (float64, 3-D), `cell_size_m` (скаляр), `origin_m` (3,).
  Загрузка только с `allow_pickle=False`.
- `stations.csv`: `station_id,x_m,y_m,z_m`.
- `events.csv`: `event_id,x_m,y_m,z_m`.
- `generation.json` (опционально): имя генератора, все параметры и `seed`.
  Также включается в SHA-256 входов в `metadata.json`.

### Шахматный пример со структурированной сеткой гипоцентров

Те же блоки скоростей `(4,2,2)` по 60 км и 98 станций на поверхности, что и
в шумовом эксперименте с глубиной событий от 30 км, но события на независимой
сетке `20×10×6 = 1200`. X/Y имеют шаг 12 км, Z — шесть внутренних уровней
между 30 и 120 км с небольшим сгущением у дна (`bottom_bias=0.15`).
Координаты *не* округляются к инверсионной сетке или узлам прямого решателя.
Из корня репозитория:

```sh
python -m projects.forward_modeling.generator \
  checkerboard_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --event-grid-shape 20 10 6 --min-depth-km 30 --bottom-bias 0.15 --seed 42
python -m projects.forward_modeling \
  checkerboard_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --refinement 32 --noise --noise-relative-sigma 0.01 \
  --noise-absolute-sigma-s 0.05 --noise-seed 42
```

Генератор пишет в `experiments/input/<ID>`, прямой расчёт — в
`experiments/output/<ID>`. Всего ожидается `1200×98 = 117600` приходов.

### Серия по размеру скоростных блоков

Варианты с теми же **байтово одинаковыми** `events.csv` и `stations.csv`,
скоростями 4750/5250 м/с и шумом 1% времени пробега + 0.05 с (`seed=42`).
Меняется только форма шахматной скоростной модели. Чтобы изменение числа
скоростных ячеек не меняло на порядок точность/стоимость FMM, число её
подразделений выбирается так, чтобы физический расчётный шаг оставался близким
к шагу 1.875 км исходного варианта с четырьмя блоками:

| Блоков по X | Форма скоростей | Куб скорости, км | `refinement` | Шаг FMM, км |
| ---: | :---: | ---: | ---: | ---: |
| 2 | `2×1×1` | 120 | 64 | 1.875 |
| 4 (исходный) | `4×2×2` | 60 | 32 | 1.875 |
| 6 | `6×3×3` | 40 | 21 | ≈1.905 |
| 8 | `8×4×4` | 30 | 16 | 1.875 |
| 12 | `12×6×6` | 20 | 11 | ≈1.818 |

Каждый новый ID имеет вид
`checkerboard_240x120x120_nxN_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42`,
где `N` — 2, 6, 8 или 12. Пример для `N=6` из корня репозитория:

```sh
python -m projects.forward_modeling.generator \
  checkerboard_240x120x120_nx6_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --blocks 6 3 3 --event-grid-shape 20 10 6 --min-depth-km 30 \
  --bottom-bias 0.15 --seed 42
python -m projects.forward_modeling \
  checkerboard_240x120x120_nx6_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --refinement 21 --noise --noise-relative-sigma 0.01 \
  --noise-absolute-sigma-s 0.05 --noise-seed 42
```

Из-за целочисленного `refinement` физический шаг FMM у 6 и 12 блоков
немного отличается от исходного. Это **не** идентичная численная дискретизация,
но отличается гораздо меньше, чем при `refinement=32` для всех моделей.

### Градиент и шесть сферических аномалий

Новый эксперимент `gradient6spheres_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42`
использует *точно те же* `stations.csv` и `events.csv`, что и структурированный
шахматный пример `(4,2,2)` выше. Скоростная модель и её `generation.json`
новые, геометрия — прежняя:

- Размер области 240×120×120 км; кубы **скоростной** сетки по 2.5 км,
  форма `(96,48,48)`. Координаты гипоцентров при этом не меняются.
- Фоновая скорость в м/с: `4600 + 1000·z/120 км`, где `z` — глубина;
  в верхней границе 4600, у дна 5600. Это 1-D профиль без горизонтальных
  изменений вне аномалий.
- Каждая аномалия ограничена сферой радиуса `R`: внутри неё добавляется
  `Δv·(1+cos(π·r/R))/2`, вне — ноль. `Δv` — пиковая добавка в центре,
  `r` — расстояние до центра. Переход через границу непрерывен.

| Центр X/Y/Z, км | Радиус, км | Пиковая добавка, м/с |
| :--- | ---: | ---: |
| 34 / 29 / 36 | 14 | +360 |
| 76 / 82 / 67 | 21 | −320 |
| 134 / 37 / 92 | 18 | +520 |
| 185 / 84 / 41 | 26 | −440 |
| 212 / 32 / 84 | 12 | +270 |
| 114 / 98 / 30 | 16 | −260 |

Создание входа и отдельный расчёт приходов из корня репозитория:

```sh
python -m projects.forward_modeling.spherical_generator \
  gradient6spheres_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --geometry-experiment \
  checkerboard_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42
python -m projects.forward_modeling \
  gradient6spheres_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --refinement 2 --noise --noise-relative-sigma 0.01 \
  --noise-absolute-sigma-s 0.05 --noise-seed 42
```

`refinement=2` даёт шаг прямого FMM 1.25 км и сетку узлов `(193,97,97)`.
Шум задаётся теми же настройками, но сами приходы и их зависящие от
пробега стандартные отклонения меняются вместе со скоростной моделью.
`generation.json` фиксирует параметры сфер и хеши заимствованных координат.
На **8 выбранных из 1200 событий** расхождение относительных времен при
переходе `refinement=2→3` составило максимум ≈0.062 с, RMS ≈0.029 с;
абсолютных — максимум ≈0.089 с, RMS ≈0.026 с. Это выборочный индикатор
сходимости, **не гарантия погрешности на всей таблице**.

### Четыре волнистых слоя и шесть компактных аномалий

Эксперимент `layered6bubbles_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42`
использует те же 98 станций и 1200 событий, что и структурированный
шахматный пример выше. Генератор сохраняет **только входные файлы**:
`model.npz`, `stations.csv`, `events.csv`, `generation.json`. Геометрия
`stations.csv` и `events.csv` байтово совпадает с исходным экспериментом.
Область 240×120×120 км разбита на кубы скорости 2.5 км (96×48×48).
На центрах вокселей фон состоит из четырёх постоянных скоростей
4600, 4850, 5150, 5400 м/с сверху вниз. Границы слоёв в километрах
(координаты `x`, `y` — км, глубина `z` направлена вниз):

```text
b1(x,y) = 30 + 6 sin(2πx/240) + 4 cos(2πy/120)
b2(x,y) = 60 + 8 sin(2πx/240 + 0.8) + 5 sin(2πy/120 + 0.3)
b3(x,y) = 90 + 6 cos(2πx/240 - 0.4) - 4 sin(2πy/120)
```

Для глубин `z < b1`, `b1 ≤ z < b2`, `b2 ≤ z < b3`, `z ≥ b3`
используются соответственно четыре скорости. При генерации проверяется,
что на всех горизонтальных центрах вокселей `0 < b1 < b2 < b3 < 120`.
Поверх фона каждая аномалия добавляет
`Δv · (1 + cos(πr/R)) / 2` при `r < R`, иначе ноль; `r` — расстояние
до центра в км. Профиль компактен и имеет непрерывную первую производную
на границе сферы; перекрывающиеся добавки суммируются.

| Центр X/Y/Z, км | R, км | Пиковая Δv, м/с |
| :--- | ---: | ---: |
| 34 / 29 / 36 | 21 | +360 |
| 76 / 82 / 67 | 31.5 | −320 |
| 134 / 37 / 92 | 27 | +520 |
| 185 / 80 / 41 | 39 | −440 |
| 212 / 32 / 84 | 18 | +270 |
| 120 / 95 / 30 | 24 | −260 |

Радиусы увеличены в 1.5 раза относительно `spherical_generator.py`, а
пиковые добавки сохранены. Центры четвёртой и шестой аномалий сдвинуты,
чтобы сферы целиком находились внутри области. Из корня репозитория:

```sh
python -m projects.forward_modeling.layered_bubbles_generator \
  layered6bubbles_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --geometry-experiment \
  checkerboard_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42
```

`generation.json` содержит параметры слоёв и аномалий, формулы границ,
ID источника геометрии и SHA-256 обеих CSV. Отдельная команда для
**последующего** расчёта прямой задачи (генератор её не запускает):

```sh
python -m projects.forward_modeling \
  layered6bubbles_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --refinement 2 --noise --noise-relative-sigma 0.01 \
  --noise-absolute-sigma-s 0.05 --noise-seed 42
```

Расчётный шаг `refinement=2` составляет 1.25 км. На **8 выбранных событиях**
переход к `refinement=3` изменил относительные времена максимум на ≈0.083 с,
RMS ≈0.030 с; это выборочный индикатор сходимости, а не гарантированная
погрешность всей таблицы из 1200 событий.

### Готовый шахматный пример

`checkerboard_240x120x120_98st_1000ev_seed42`:

- Размер `x=240`, `y=120`, глубина `z=120` км; `z` направлена **вниз**,
  поверхность `z=0`. Начало координат `(0,0,0)`.
- Форма массива скоростей `(4,2,2)`, размер скоростного куба `60 км`.
  В ячейке `(i,j,k)` скорость `4750 м/с` при чётной сумме `i+j+k`, иначе
  `5250 м/с`. В общей сложности восемь блоков каждой скорости.
- `98 = 14×7` станций на регулярной прямоугольной сетке, по центрам
  одинаковых участков поверхности; все имеют `z=0`. Это **не** центры
  скоростных блоков.
- `1000` событий внутри области, глубина строго **больше 10 км** и меньше
  `120 км`. `scrambled Sobol` обеспечивает квазиравномерное покрытие,
  `seed=42` — воспроизводимость. Распределение по глубине имеет плотность
  `p(t)=1-b+2bt`, где `t` — относительная глубина от 10 до 120 км и
  `b=0.15`: у дна плотность немного выше, чем вверху. Значения не
  округляются к расчётной или скоростной сетке.
- ID станций вида `STA_01`…`STA_98`, событий — `EVT_0001`…`EVT_1000`.
  Для нового прогона с другим seed или скоростями используйте новый ID.

Для данного набора один расчёт `refinement=32` даёт расчётный шаг `1.875 км`,
форма поля `(129,65,65)`. В `arrivals.csv` записано `98 000` времен.
На **всех 1000 событиях** расхождение относительных времен между `16` и `32`
составило `max=0.803 с`, `RMS=0.131 с`. На **10 выбранных событиях**
максимальное расхождение относительных времен при переходе с `32` на `64`
составило около `0.189 с` (`0.199 с` для абсолютных). Проверка `32→64`
**не проводилась для всех событий**; выборочная оценка не является гарантией
точности полученной таблицы. Сохранено решение на `refinement=32`, а не `64`.

**Выходы / наблюдения:**

- `arrivals.csv`: **только** `station_id,event_id,arrival_time_s` для всех пар.
- `metadata.json`: версии решателя и обёртки, численные настройки, соглашения
  о времени/единицах, SHA-256 входов, длительность расчёта и результаты
  проверки сходимости, если она запрошена, а также конфигурация шума наблюдений.

Координаты событий и истинная скорость в output не копируются. Для запуска
EMTomo укажите имя эксперимента:

```sh
python projects/EMTomo/main.py <EXPERIMENT_ID> --validate-only
```

Затем запустите команду без `--validate-only` для инверсии.
Подробности — `projects/EMTomo/EXPERIMENTS.md`. Адаптер EMTomo читает
наблюдения и станции по ID, а модель и истинную геометрию — из входной папки.
Координаты станций нужны и для инверсии: берите их из `input/.../stations.csv`.
ID связывают таблицы; при построении матрицы EMTomo используйте **одинаковый
порядок станций** для столбцов времён и массива координат. Истинные координаты
событий не должны попадать в восстановление как известные положения.

Входы и выходы не перезаписываются. Для другой уже опубликованной версии
эксперимента используйте новый ID. Файлы публикуются целой папкой после успеха;
обычная ошибка очищает временные файлы. Аварийное завершение процесса может
оставить скрытые `.ID.lock` / `.ID.tmp-*`; удалять их вручную следует только
убедившись, что расчёт больше не выполняется. Изменение входных файлов во время
расчёта проверяется повторным SHA-256 и приводит к отказу публикации.
Данные экспериментов исключены из Git, код и описание формата — нет.

## Численная схема и точность

В EMTomo используется `skfmm` с источником в центре ячейки. Здесь:

1. Независимая реализация FMM **PyKonal**, float64, с upwind-разностями до второго порядка.
2. Независимое сгущение: `h = cell_size_m / refinement`. По умолчанию `refinement=2`.
   Расчётные узлы включают границы; массив имеет размер
   `(nx*refinement+1, ny*refinement+1, nz*refinement+1)`.
3. Внутри вокселей сохраняется исходная скорость. На интерфейсных узлах
   усредняется **медленность** соседних вокселей. Численная ширина интерфейса
   уменьшается вместе с `h`, исходная модель при этом не меняется.
4. В небольшой области вокруг **точного** источника начальные времена
   вычисляются интегрированием медленности вдоль прямых отрезков через воксели.
   `source_radius_cells=2` задаёт размер этой области в расчётных ячейках.
   Это локальное приближение, не точный расчёт преломлённых лучей. Начальные
   времена находятся в очереди FMM и могут изменяться при распространении.
5. Для точного приёмника интерполируется регуляризованная величина
   `T(x)/distance(x, source)`, затем восстанавливается истинное расстояние.
   Это устраняет геометрическую ошибку интерполяции расстояния около источника,
   но **не** является решением факторизованного уравнения эйконала и не исправляет
   ошибки самого поля. При совпадении источника и приёмника время равно нулю.
6. Поля рассчитываются последовательно от событий: в памяти не хранится
   полный набор 3-D полей. Добавление/перестановка событий не меняет способ
   решения существующих пар.

**Точность не гарантируется одним выбором библиотеки или параметра.**
Есть погрешности источника, дискретизации интерфейсов и интерполяции.
Сходимость может быть немонотонной, особенно при резких контрастах. Слишком
большую область прямолинейной инициализации задавать не следует: это не замена
локальному преломлённому решению.

`check_convergence()` / `--check-convergence` сравнивают `r` и `2r`:

- `max_abs_difference_s`, `rms_difference_s` — различия **относительных** приходов;
- `max_absolute_time_difference_s`, `rms_absolute_time_difference_s` — различия
  абсолютных времён распространения, чтобы не скрыть общую ошибку источника.

`--max-difference-s` проверяет оба максимума; это критерий согласованности
двух сеток, **не строгая оценка истинной ошибки**. В `arrivals.csv` сохраняется
решение на **запрошенном `r`**, а не на проверочной `2r`-сетке. Для эталонного
датасета рекомендуются проверки нескольких разрешений, например `r`, `2r`, `4r`,
и аналитические тесты на характерных контрастах и расстояниях.

Удвоение refinement увеличивает число пространственных узлов примерно в 8 раз,
а не в 2. Отличия решателя, источника и сетки снижают риск *inversion crime*,
но не доказывают его отсутствие. Не используйте настройки прямой задачи как
обоснование точности без проверки сходимости на конкретном эксперименте.

## Проверки

```sh
python -m pip install pytest
python -m pytest projects/forward_modeling/tests -q
```

Есть аналитические проверки однородной среды, преломления по закону Снеллиуса
и головной волны в быстром слое; проверки точных координат внутри одной ячейки,
граничных точек, переноса начала координат, относительных времён, формата,
идентификаторов, атомарной публикации и порога сходимости. Допуски в тестах
относятся только к их геометрии, а не являются гарантией для всех моделей.

Старый `EMTomo/instruments/instruments_synthetic.py` оставлен для совместимости
существующих сценариев. Новый workflow генерирует входы и решает прямую задачу
**раздельно**; EMTomo читает результат по имени эксперимента, не запуская
решатель прямой задачи повторно. Отображение в viewer — отдельный этап.
