# L-curve: постфактум выбор итерации без истинной скорости

Новый CSV: `hard_soft_lcurve_avg_abs_pct_dev.csv` — все прежние 38 пар.
График: `../figures/results/soft_gain_vs_hard_avg_abs_pct_dev_lcurve.png` и `.pdf` —
36 пар, без `section6_pair05` и `section6_pair06`. Это две пары сложной аномалии
с подтверждённым однородным стартом 5000 м/с; из CSV они не удалены, а помечены
`included_in_plot=False` и причиной исключения. Все остальные пары сохранены.

## Одно правило для hard и soft

Для каждого сохранённого модельного checkpoint V_k строятся две координаты:

1. Невязка — pooled RMSE межстанционных разностей остатков из ранее проверенного
   `residual_metrics_cache.json` (те же обучающие события, без новых решателей).
2. Изменение модели — `||s_k - s_0||_2 / ||s_0||_2`, где `s = 1 / V`.

Обе координаты берутся в log10 и независимо нормируются в [0,1] по диапазону
траектории этого рана. Между первой и последней точками проводится хорда.
Выбирается внутренняя точка с **максимальным абсолютным перпендикулярным
расстоянием до хорды**. При точном равенстве берётся самая ранняя.

Если точек меньше трёх, ось вырождена или кривая прямая, выбирается последняя
доступная точка; причина записана явно. В этом наборе 62 уникальных рана получили
геометрический локоть, а два коротких рана (coverage=0, лимит 3) — fallback из-за
только двух доступных ненулевых точек. В разных сравнениях один и тот же hard
может переиспользоваться; выбор для него рассчитан один раз.

Это простая **ретроспективная эвристика**, не независимая валидация, не доказанная
граница начала подгонки шума и не онлайн-остановка: положение хорды зависит от
доступного конца траектории. Не проверяем «удачность» локтя по истинной модели и
не подстраиваем правило под её минимум.

## Выравнивание времени

`iter_k/model.npy` и его `residuals.npy` относятся к модели V_k, то есть модели
**после k обновлений**, до следующего M-step. Соответствующая ошибка скорости
находится в `quality.jsonl` под индексом **k−1**, не k.

V_0 исключена из log-кривой, потому что изменение относительно старта равно нулю.
Финальная V_N тоже не включена: сохранённые остатки заканчиваются на V_(N−1).
Новую финальную локализацию/FMM не запускали. Следовательно, у рана из N полных
обновлений обычно N−1 доступных ненулевых модельных checkpoints.

Все выборы 64 уникальных ранов фиксируются **до чтения любых `quality.jsonl`**.
После этого выбранные checkpoints оцениваются по `avg_abs_pct_dev`, то есть
истинная модель используется только для оценки, а не для выбора.

## Столбцы

- `hard_avg_abs_pct_dev_at_lcurve` / `soft_avg_abs_pct_dev_at_lcurve` — ошибка
  скорости на выбранной модели (%), **не минимум ошибки по истине**.
- `*_selected_update_number` — число завершённых обновлений у выбранной модели.
- `*_residual_iteration_index` — k в `iter_k`, равен числу обновлений модели.
- `*_quality_iteration_index` — k−1 в `quality.jsonl`.
- `*_residual_rmse_s_at_lcurve`, `*_relative_slowness_change_at_lcurve` —
  исходные координаты L-кривой.
- `*_selection_reason`, `*_n_lcurve_checkpoints` — правило/причина fallback и
  количество доступных точек.
- `soft_gain_percent = 100 * (E_hard,L - E_soft,L) / E_hard,L`.
- `selection_uses_truth=False`, `evaluation_uses_truth=True`.

Полные траектории, расстояния, выборы и хеши моделей/входов записаны в
`lcurve_selection.json`. На графике сохранены прежние цвета серий и градиент
**фактического**, а не предполагаемого шума шахматки: 0.5×–2×, темнее — шумнее.
