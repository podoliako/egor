# Сравнения hard/soft: минимальный RMSE остатков

## Файлы

- `hard_soft_min_residual_rmse.csv` — **38 пар с обеими метриками**, секции 2–6.
- `hard_soft_incomplete_pairs.csv` — 4 сопоставленные пары, в которых хотя бы один
  ран не имеет ни одной полностью завершённой итерации. Существующие значения
  hard сохранены, отсутствующие значения пустые, а не нулевые.
- `hard_soft_unpaired_runs.csv` — 8 ранов без соответствующего противоположного
  режима: 6 soft-пилотов на 10 событиях, однократный soft на полном каталоге и
  исходный hard разлома K15/top1. Несопоставимые настройки не объединены насильно.
- `residual_metrics_cache.json` — траектории метрики каждого рана, минимум,
  количество событий/пар и проверяемая привязка к метаданным/complete markers.

принадлежность к новой секции неоднородностей не была подтверждена.

## Определение основной метрики

Для события e сохранённая матрица `iter_k/event_e/residuals.npy` содержит
`R_e[i,j] = r_e[i] - r_e[j]`, где r — невязка времени наблюдение минус расчёт.
Используется верхний треугольник `i < j` без диагонали. Значения NaN,
соответствующие неиспользованным станциям, исключаются; бесконечности, отсутствие
файла события или отсутствие всех конечных пар являются ошибкой, а не поводом
молча отбросить событие.

Основной показатель каждой итерации (секунды):

```text
RMSE_k = sqrt(sum_e sum_{i<j, finite} R_e[i,j]^2 / N_finite_station_pairs)
```

Это **RMSE межстанционных разностей остатков**, не RMSE скоростной модели,
не ошибка координат гипоцентров и не held-out/control RMSE. Остатки относятся к
первой активной (MAP) гипотезе E-step **до обновления скорости этой итерации**.
Новая локализация после финального M-step не выполнялась.

Поля `hard_min_residual_rmse_s` / `soft_min_residual_rmse_s` содержат минимумы
этой метрики по полностью опубликованным итерациям каждого рана. Минимумы hard и
soft выбираются **независимо**, их итерации могут различаться. При точном равенстве
берётся самая ранняя итерация. Проверен каждый ожидаемый event-файл, без
подвыборки событий. При первичном сборе прочитано 2 734 398 файлов из 785
завершённых итераций 74 ранов; ещё 6 ранов не имели завершённых итераций.

Для сверки со сводным графиком вьювера отдельные поля
`hard_min_mean_event_rms_s` / `soft_min_mean_event_rms_s` содержат независимые
минимумы **среднего по событиям событийного RMS**, то есть
`mean_e sqrt(mean_{i<j, finite} R_e[i,j]^2)`. Это другой порядок усреднения,
не основная pooled-метрика. Его лучшие индексы записаны отдельно.

В v1.5 остатки обучающие: контрольные пики исключены. Поэтому значения v1.4 и
v1.5 не следует считать рассчитанными по одному и тому же набору наблюдений.
Сравнения внутри каждой пары проверены; межсекционные абсолютные значения
могут различаться из-за геометрии, шума и разбиения.

## Соответствие пар и столбцы

Проверяются ID данных, хеш истинной модели в метаданных, хеш сохранённого старта,
координаты станций, сетки, версия метода, количество циклов, K/top-N/dmin,
регуляризация, модель шума, контрольный mask и параметры остановки. Для новых
неоднородностей также сохраняется когорта `study_manifest`: остановленные первые
попытки не подменяются успешными p12-перезапусками.

Для разломного скрининга используются явные `hard_control` из его manifest,
с повторной проверкой совместимости. Температура и расписание soft могут
отличаться от hard, как предусмотрено исходным скринингом: один hard-контроль
сравнивается с несколькими soft-температурами. Переиспользование показано в
`hard_control_reuse_count`. **38 строк не означают 38 независимых реализаций данных.**

Основные столбцы:

- `pair_id`, `section`, `section_name`, `experiment_id` — группа сравнения.
- `hard_run_id`, `soft_run_id` — точные исходные раны.
- `*_min_residual_rmse_s` — минимум основной метрики, в секундах.
- `*_best_iteration_index` — индекс `iter_k`, с нуля.
- `*_best_iteration_number` — тот же номер с единицы.
- `*_complete_iterations`, `*_has_final_model`, `*_metric_status` — полнота данных.
- `*_n_pairs_at_minimum` — число конечных межстанционных пар в лучшей итерации.
- `*_min_mean_event_rms_s`, `*_best_mean_event_iteration_index` — альтернативная
  метрика для сверки со вьювером и её собственная лучшая итерация.
- `soft_gain_percent = 100 * (hard_min - soft_min) / hard_min` — положительный
  результат означает меньшую невязку soft; это не выигрыш восстановления истины.
- Остальные столбцы описывают настройки и начальную модель.

## Воспроизведение

Из корня репозитория:

```sh
venv/bin/python projects/EMTomo/studies/article_inventory/residual_metrics.py --help
venv/bin/python projects/EMTomo/studies/article_inventory/residual_metrics.py --workers 16
venv/bin/python projects/EMTomo/studies/article_inventory/export_residual_pairs.py
venv/bin/python -m pytest \
  projects/EMTomo/studies/article_inventory/test_residual_metrics.py \
  projects/EMTomo/studies/article_inventory/test_export_residual_pairs.py -q
```

Кэш привязан к снимку инвентаризации, метаданным и complete markers. Исторические
остатки предполагаются неизменяемыми; после их ручного редактирования нужен
`--refresh`. Скрипты не запускают FMM/EM, не изменяют исходные раны и не обращаются
к лучевым файлам. Выбор минимальной итерации является ретроспективным, не новым
критерием остановки инверсии.
