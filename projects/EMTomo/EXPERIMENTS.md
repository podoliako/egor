# Запуск EMTomo по сохранённому эксперименту

**Основной способ запуска:** сначала генерировать и считать наблюдения независимой
прямой задачей `projects/forward_modeling`, затем передавать EMTomo только **имя**
эксперимента. При запуске EMTomo не строит события и не пересчитывает
синтетические времена.

Из папки `projects/EMTomo`:

```sh
python main.py checkerboard_240x120x120_98st_1000ev_seed42 --validate-only
python main.py checkerboard_240x120x120_98st_1000ev_seed42 --workers 1
```

`--validate-only` проверяет входные и выходные данные и собирает конфигурацию
инверсии **без запуска EM, JIT-прогрева и записи runs**. Для полного эксперимента
с уже подготовленными данными создаётся инверсионная сетка `(24, 12, 12)` с
шагом `10 000 м`. По умолчанию — 7 циклов, subdivision 3, начальная
**однородная** скорость 5000 м/с. Точная скоростная модель из входов *не*
используется для начального приближения. `--workers 1` рекомендован как
осторожный первый запуск при 1000 событиях; затем можно изменять ресурсы и
параметры инверсии через конфигурацию `ExampleConfig` / `main(config,
experiment_id="...")`. Длинный полный запуск здесь не выполнялся.

Дополнительные CLI-параметры: `--experiments-root PATH` (по умолчанию
`projects/forward_modeling/experiments` вне зависимости от cwd),
`--cell-size-m`, `--subdivision`, `--cycles`, `--workers`, `--runs-dir`,
`--lambda-reg`, `--coverage-damping-power`, `--max-velocity-step-fraction`,
`--run-name`. Например, параметры старого checkerboard-run (кроме версии кода):

```sh
python main.py checkerboard_240x120x120_98st_1000ev_seed42 \
  --cell-size-m 10000 --subdivision 8 --cycles 14 --workers 24 \
  --lambda-reg 0.05 --coverage-damping-power 1.5 \
  --max-velocity-step-fraction 0.005 --run-name checkerboard_meta_sub8_cov15_14cycles
```

Этот запуск длительный (старый run занимал примерно 100 минут); не запускайте
повторно, пока такой же расчёт ещё выполняется.
Шаг инверсии должен точно разбивать размеры области по всем осям.
`run_name` содержит ID исходного эксперимента. Результаты инверсии сохраняются
в привычном `runs/`. Новый viewer показывает только runs с подтверждённой
связью с исходным экспериментом (ID и SHA-256 модели); старые runs без этой
связи не выводятся.

### Откуда берутся данные

- `output/<ID>/arrivals.csv`: наблюдения в секундах. Наблюдения привязываются
  к `event_id` и `station_id`, а не к порядку строк CSV. Пропущенные,
  дублированные и неизвестные пары вызывают ошибку. Для каждого события
  первое время должно быть нулём.
- `input/<ID>/stations.csv`: **точные** координаты станций в метрах; порядок
  станций согласован со столбцами матрицы `(events, stations)`. EMTomo на этапе
  внутреннего FMM по-прежнему переводит станцию в индекс расчётной ячейки;
  исходные координаты в адаптере не округляются.
- `input/<ID>/model.npz`: размеры области и истинная скоростная модель. Истина
  используется **только для метрик качества и отображения эталона в viewer**;
  начальная модель инверсии однородная. `true_model.npy` старого формата не
  считается оригиналом: viewer берёт непосредственно `input/<ID>/model.npz`.
- `input/<ID>/events.csv`: ID определяют порядок строк матрицы. Координаты
  истинных событий **не передаются** в восстановление и в сохранённые метаданные run.
  Viewer отдельно загружает их для маркеров, перехода `True Y` и `Hypo Distance`,
  проверяя хеши входов по `output/<ID>/metadata.json`. Порядок событий — порядок
  строк входного CSV, как при подготовке инверсии.
- `output/<ID>/metadata.json`: проверяются единицы SI, относительное начало
  отсчёта и SHA-256 всех файлов входа (включая `generation.json`, если он есть).
  Поддерживается пока только начало модели `(0, 0, 0)` в локальных метрических
  координатах. Данные не должны меняться между решением прямой и обратной задач.

### Маленький воспроизводимый прогон

Из корня репозитория `egor` (или с аналогичными путями):

```sh
python -m projects.forward_modeling.generator em_tiny_4x2x2 \
  --lengths-km 4 2 2 --blocks 4 2 2 --surface-stations 2 2 \
  --events 8 --min-depth-km 0.25 --seed 7
python -m projects.forward_modeling em_tiny_4x2x2 --refinement 4
python projects/EMTomo/main.py em_tiny_4x2x2 \
  --cell-size-m 1000 --subdivision 1 --cycles 1 --workers 1 --validate-only
python projects/EMTomo/main.py em_tiny_4x2x2 \
  --cell-size-m 1000 --subdivision 1 --cycles 1 --workers 1
```

Генерация создаёт 4 станции и 8 событий; прямая задача записывает 32 прихода.
Эксперименты и результаты runs не перезаписываются автоматически, поэтому для
новой генерации используйте другой ID. Запуск CLI возможен и из корня проекта,
и из папки EMTomo. Файлы больших и маленьких экспериментов исключены из Git;
команды выше позволяют воспроизвести тестовый пример.

### Viewer

```sh
python projects/EMTomo/server.py  # из корня проекта
```

Или из `projects/EMTomo`: `python server.py`. Если runs и данные находятся
не в стандартных каталогах, передайте `--runs-dir` и `--experiments-root`.
Откройте `http://localhost:5050` (Plotly загружается через CDN; для него нужен
доступ браузера к сети).

Левая панель — модель инверсии выбранной итерации, правая — исходные скоростные
блоки из независимого forward input. Обе оси X/Z и общий Y задаются в **км**;
границы крупных скоростных блоков нанесены на оба среза. Шаг перемещения по Y
по умолчанию — 1/10 протяжённости области по Y, его можно поменять в поле
`Step` (км). Для скоростей шкала цветов общая и не переключается; Δs имеет
отдельную симметричную шкалу, так как измеряется в других единицах. Разрешение
среза инверсии повышено до 8× по каждой пространственной оси (не более 240
образцов на ось), при этом backend отдаёт только двумерный срез и ограничивает
размер ответа. Истина остаётся **на своей исходной крупной сетке**, без
интерполяции к сетке инверсии. Старые runs viewer намеренно не поддерживает.

События отображаются в точных координатах: прозрачность плавно уменьшается
с расстоянием до среза Y (характерный масштаб — 1/10 ширины области), независимо
от размера ячеек и шага ползунка. Подпись получает выбранное событие; остальные
ID доступны при наведении, чтобы тысяча подписей не закрывала модель.

`Hypo Weights` сохраняет мелкую FMM-сетку. Его `Y layer` — индекс слоя с шагом 1;
рядом отображается координата центра слоя в км. Кнопка `True Y` переходит в слой,
содержащий истинное положение выбранного события. Шаг скоростных панелей на
эту навигацию не влияет. `Hypo Distance` показывает расстояние в метрах от
гипотезы с наибольшим весом до истинного события. Для ещё не записанных гипотез
текущей итерации данных пока нет.

Docker-viewer монтирует `runs`, `experiments/input` и `experiments/output`
только для чтения. Из output для отображения требуется лишь `metadata.json`;
матрица приходов и зависимости прямого решателя viewer не нужны.

Проверки кода:

```sh
python -m pytest "projects/EMTomo/tests and examples" -q
python -m pytest projects/forward_modeling/tests -q
```

Старые скрипты checkerboard/geysers вызывают `main(config)` без ID и пока
сохраняют прежний путь генерации для обратной совместимости. Основной CLI
`main.py <EXPERIMENT_ID>` использует **только** заранее рассчитанные наблюдения.
Их автоматическую генерацию при запуске томографии намеренно не добавляли.
