# Запуск EMTomo по сохранённому эксперименту

**Основной способ запуска:** сначала генерировать и считать наблюдения независимой
прямой задачей `projects/forward_modeling`, затем передавать EMTomo только **имя**
эксперимента. При запуске EMTomo не строит события и не пересчитывает
синтетические времена.

Из папки `projects/EMTomo`:

```sh
python main.py checkerboard_240x120x120_98st_1000ev_seed42 --validate-only
python main.py checkerboard_240x120x120_98st_1000ev_seed42 --workers 1
```

`--validate-only` проверяет входные и выходные данные и собирает конфигурацию
инверсии **без запуска EM, JIT-прогрева и записи runs**. Для полного эксперимента
с уже подготовленными данными создаётся инверсионная сетка `(24, 12, 12)` с
шагом `10 000 м`. По умолчанию — 7 циклов, subdivision 3, начальная
**однородная** скорость 5000 м/с. Точная скоростная модель из входов *не*
используется для начального приближения. `--workers 1` рекомендован как
осторожный первый запуск при 1000 событиях; затем можно изменять ресурсы и
параметры инверсии через конфигурацию `ExampleConfig` / `main(config,
эксперимент_id="...")`. Длинные полные запуски описаны ниже.

Дополнительные CLI-параметры: `--experiments-root PATH` (по умолчанию
`projects/forward_modeling/experiments` вне зависимости от cwd),
`--cell-size-m`, `--subdivision`, `--cycles`, `--workers`, `--runs-dir`,
`--weights-top-n`, `--weights-min-distance`, `--candidate-mode`, `--temperature`,
`--weight-noise-relative-sigma`, `--weight-noise-absolute-sigma-s`,
`--weight-model-sigma-s`, `--lambda-reg`,
`--smoothness-reg`, `--initial-gradient-m-s TOP BOTTOM`,
`--initial-layer-boundaries-km Z...`, `--initial-layer-velocities-m-s V...`,
`--coverage-damping-power`, `--max-velocity-step-fraction`, `--run-name`.
Например, параметры старого
checkerboard-run (кроме версии кода):

```sh
python main.py checkerboard_240x120x120_98st_1000ev_seed42 \
  --cell-size-m 10000 --subdivision 8 --cycles 14 --workers 24 \
  --lambda-reg 0.05 --coverage-damping-power 1.5 \
  --max-velocity-step-fraction 0.005 --run-name checkerboard_meta_sub8_cov15_14cycles
```

Этот запуск длительный (старый run занимал примерно 100 минут); не запускайте
повторно, пока такой же расчёт ещё выполняется.
Шаг инверсии должен точно разбивать размеры области по всем осям.

Для эксперимента с градиентом и сферами можно явно задать **приближённый**
1-D начальный фон, не передавая истинную модель инверсии:

```sh
python main.py gradient6spheres_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --initial-gradient-m-s 4700 5500 --cell-size-m 10000 --subdivision 9 \
  --cycles 12 --workers 24 --weights-top-n 1 --lambda-reg 0.05 \
  --coverage-damping-power 1.5 --max-velocity-step-fraction 0.005 \
  --run-name gradient6spheres_approx_bg_sub9_12cycles
```

Значения 4700 и 5500 м/с — заданные на верхней и нижней **границах
области**, при подготовке инверсии они вычисляются в центрах её ячеек.
Истинный фон прямого эксперимента — 4600→5600 м/с, а сферы вообще не
входят в начальную модель. Метаданные run записывают заданные границы,
`initial_model.npy` — фактические значения в ячейках. Без опции старт
остаётся однородным 5000 м/с.

Для эксперимента с волнистыми слоями и баблами можно использовать
**горизонтальные** приблизительные стартовые слои (без волнистости и баблов):

```sh
python main.py layered6bubbles_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42 \
  --initial-layer-boundaries-km 30 60 90 \
  --initial-layer-velocities-m-s 4700 4950 5100 5300 \
  --cell-size-m 10000 --subdivision 9 --cycles 12 --workers 24 \
  --weights-top-n 1 --lambda-reg 0.05 --coverage-damping-power 1.5 \
  --max-velocity-step-fraction 0.005 --run-name layered6bubbles_approx_horizontal_sub9_12cycles
```

Это явно заданные границы в км от поверхности и скорости слоёв сверху вниз
в м/с. Истина имеет средние границы около 30/60/90 км, но они зависят от
X/Y, а реальные скорости слоёв 4600/4850/5150/5400 м/с. Начальная
модель строится только из этих CLI-параметров; по Z скорость берётся в
центрах ячеек инверсии. Одновременно с `--initial-gradient-m-s` задавать
слои нельзя. Параметры записываются в `meta.json` и `initial_model.npy`.

### Вероятности гипотез гипоцентра в новых запусках

Начиная с новой реализации, веса выбранных кандидатов вычисляются из
**гауссова правдоподобия относительных времён**. Для станции `i` дисперсия
абсолютного прихода задаётся как
`σ_i² = (relative_sigma × T_i)² + absolute_sigma_s² + model_sigma_s²`,
где `T_i` — рассчитанное время до станции из данного кандидата. Неизвестное
общее время начала события интегрируется с плоским априорным распределением:
поэтому шум выбранной станции с первым приходом **не** добавляется независимо
в каждую разность со всеми станциями. Для каждого кандидата учитываются
невязка, разные `σ_i` и нормировка гауссова правдоподобия. Разности невязок
**не** используются как масштаб собственных весов: при `top_n=2` результаты
перестали принудительно равняться 0.731/0.269 для всех событий.

При запуске по сохранённому эксперименту `relative_sigma` и
`absolute_sigma_s` автоматически берутся из `output/<ID>/metadata.json`
(если шум выключен — обе равны нулю). Переопределить предположенную модель
наблюдений можно флагами `--weight-noise-relative-sigma` и
`--weight-noise-absolute-sigma-s`; `--weight-model-sigma-s` задаёт добавочную
неопределённость численного расчёта/несовершенной скоростной модели
(**по умолчанию 0.2 с**, эвристика, не измеренная по конкретному эксперименту).
Принятые значения и версия формулы записываются в `meta.json` нового run.
`--temperature=1` соответствует этому правдоподобию; отличная от единицы
температура даёт **искусственно смягчённое/заострённое** распределение.

Это нормированные вероятности **условно на ограниченный `top_n` набор
кандидатов, равный априорный вес их точечных гипотез и предположенные
независимые ошибки**. Отбор делается по грубой парной невязке, непрерывное
положение внутри каждой ячейки оптимизируется по ней же, но интегрирование
по объёму ячейки и по *невыбранным* гипоцентрам не выполняется. Корреляции
ошибок прямого решателя и ошибки самой скоростной модели лишь приближённо
учтены параметром `model_sigma_s`. Поэтому это **не** автоматически
калиброванная вероятность истинного гипоцентра в полном объёме: перед
интерпретацией доверительных интервалов стоит проверить покрытие на
синтетике и подобрать реальный масштаб ошибок. Старые runs не пересчитываются: старые параметры помечены версией `1.1`,
новые запуски — `1.2`. Для сравнения с новой формулой EM нужно запускать
заново. Для отдельной функции `compute_weights_from_misfit` теперь обязателен
явный `misfit_scale` в единицах невязки вместо масштаба из отобранных
кандидатов; сама инверсия использует гауссово правдоподобие, а не эту функцию.

### Сравнение методов после согласования шага инверсии (v1.3)

`--candidate-mode soft` (по умолчанию) и `--candidate-mode hard` используют
**один и тот же** отбор `--weights-top-n K`, уточнение кандидатов и вычисление
их вероятностей. `hard` оставляет в нормальных уравнениях только кандидата с
максимальным весом, `soft` учитывает все K. Это корректный контроль *мягкого
назначения* при одинаковом поиске; запуск `K=1` сравнивает также ширину поиска.
В `weights.npz` поле `weight_values` — веса, фактически участвовавшие в
инверсии (в режиме `hard` это one-hot); координаты всех K кандидатов сохраняются.

Шаг обновления скорости теперь использует `1/σ_i²` для каждой станции и
каждого кандидата из той же модели ошибок, что и веса, и исключает общее
неизвестное время начала события взвешенным центрированием. Станции, до которых
не дошёл луч, исключаются из шага скорости. Это **изменяет масштаб** матрицы
чувствительности и эффективное действие регуляризации. Результаты v1.2 и v1.3
нельзя считать запусками одного алгоритма при одинаковом `lambda_reg`;
численные выводы ниже относятся к v1.2 и требуют повторной проверки на v1.3.
Данные из `forward_modeling` остаются неизменными: EMTomo их не генерирует.

Перед сравнением скоростей задайте одинаковые `K`, `--weights-min-distance`,
начальную модель, наблюдения и геометрию для пары `soft`/`hard`, используйте
`--temperature 1`; проверьте устойчивость по `--weight-model-sigma-s` (0.2 с —
эвристика, а не уровень измеренного шума) и регуляризации. `weights-min-distance`
измеряется в *мелких* ячейках: физическое расстояние примерно равно
`weights_min_distance × cell_size_m / subdivision`. При смене дискретизации
пересчитайте целевое расстояние вручную.

**Оставшиеся приближения:** сначала отбираются ячейки по невзвешенной парной
невязке в центрах, затем положения уточняются по той же невязке; отбор не
гарантирует топ-K по гауссову правдоподобию при неодинаковых `σ_i`. Массы ячеек
не интегрируются, коррелированная модельная ошибка описана независимой
добавкой `model_sigma_s`; это не полный пространственный posterior. Инверсия
строит поля от станций, привязанных к центрам мелких ячеек
(`metric_to_cell_index`), тогда как независимая прямая задача допускает станции
на границе области и вне центров ячеек. Проверяйте влияние этого смещения и
сходимость по `subdivision`, особенно для поверхностных станций. Ограничение
шага скорости и регуляризация также не дают общей гарантии монотонности EM.

Локальные `runs/` и `pictures/` содержат результаты и игнорируются Git;
в `runs/` имеются также скрипты и манифесты пилотов, на которые ссылается этот
документ. **Не удаляйте `runs/` и не применяйте `git clean -fdx` без отдельного
архивирования:** иначе будут потеряны рецепты воспроизведения. Старые
checkerboard/Geysers launchers с синтетикой внутри EMTomo перенесены в
[`archive/legacy_synthetics/`](archive/README.md), вместе с внутренним
генератором наблюдений и прежней веткой `main(config)`; старые примеры и
удаляющий скрипт — в `archive/legacy_misc/`. Активный `main.py` запускает
инверсию только по ID готового эксперимента. Инструкция по запуску — в архиве.
Исторические отчёты ниже сохранены без переписывания.

### Исследование распределения гипоцентров (новая формула весов, v1.2)

Сохранены **три** взаимосвязанных тестовых эксперимента для сравнения
`top_n` без уменьшения разрешения FMM: `study_multi_layered6bubbles_400ev_seed42`,
`study_multi_gradient6spheres_400ev_seed42` и
`study_multi_layered6bubbles_400ev_35st_seed42`. Первые два имеют одинаковые
400 событий и 98 поверхностных станций, но разные истинные модели; в каждом
из 200 горизонтальных столбцов взято по два разных уровня глубины. Третий
имеет те же события и слоистую истину, но 35 пространственно распределённых
станций (наблюдения повторно нормированы на первый приход *среди оставшихся*
станций). Все времена взяты из ранее посчитанной прямой задачи; FMM для
прямой задачи не пересчитывался. Рецепты и входные SHA-256:
`runs/multi_hypothesis_study_20261001/make_subsets.py`, `make_sparse.py`,
`manifest.json`, `sparse_manifest.json` (все данные и `runs/` локальные,
исключены из Git).

Перед инверсией проведён **только** пилот выбора гипоцентров на 36 одинаковых
событиях по шести уровням глубины (`pilot_v1.json`, `pilot_sparse_v1.json`).
Расчётные поля станции построены как в инверсии: инверсионная ячейка 10 км,
`subdivision=9`, мелкая ячейка ≈1.111 км, `skfmm`; без трассировки лучей и
без обновления скорости. При указанной наблюдательной ошибке 1% времени
пробега плюс 0.05 с и модельной ошибке 0.2 с кандидаты с минимальным
расстоянием `d=9` мелких ячеек практически не несут дополнительной массы
(для 98 станций в пилоте нет событий со вторым весом >0.01); `d=27`
также бесполезен. При `d=1` среднее эффективное число гипотез близко к
`top_n=5/10`, но они кластеризуются около того же максимума (характерный
разброс ≈2–3.5 км). При *гипотетической* ошибке модели 1 с и `d=9`
второй кандидат часто значим и может находиться ≈20 км от первого.
Редкая сеть: при `d=9`, ошибке модели 0.2 с второй вес >0.01 был в 5/36
событий, при 1 с — в 36/36. Это **не** доказательство преимущества
множественных гипоцентров: увеличение ошибки модели произвольно расширяет
распределение; при сильном разнесении гипотез пилотная ошибка локализации
относительно известных синтетических координат часто даже увеличивалась.

Идёт последовательная 15-комбинационная инверсия (`study_runs.py`, статус
`study_runs.json`) при **том же `subdivision=9` во всех случаях**, четырёх
циклах, `λ=0.5`, coverage power 3, максимальном шаге скорости 0.005, без
сглаживания. Для каждой из трёх геометрий неизменны начальная модель,
наблюдения и станции; матрица `(top_n, min_distance, model_sigma_s)`:
`(1,1,0.2)`, `(5,1,0.2)`, `(10,1,0.2)`, `(10,1,1.0)`, `(10,9,1.0)`.
Таким образом, сравнение 1/5/10 при `d=1` изолирует число гипотез;
сравнение `(10,1,1.0)` и `(10,9,1.0)` изолирует разнесение; 0.2→1 с —
отдельная *чувствительность к предположению о шуме модели*, а не улучшение
алгоритма. По версии 1.2 эти прогоны **не сопоставимы напрямую** со старыми
версиями 1.1. Результаты можно пересчитать без дорогой инверсии командой
`python runs/multi_hypothesis_study_20261001/report.py` из `projects/EMTomo`:
`report.json` содержит RMS скорости относительно истины, корреляцию латеральных
аномалий, невязку, эффективное число гипотез, массу вне 10 км от MAP,
разнесение кандидатов с весом >0.01 и парные ошибки MAP/апостериорного
среднего относительно истинных событий (истина используется **только при
оценке**). `iter_i/model.npy` соответствует модели после `i`
обновлений, а строка `quality.jsonl` с `iter=i` — после `i+1` обновлений.
Модель после четвёртого обновления в `report.json` **восстановлена** из
`iter_3/model.npy` и `iter_3/delta_s.npy` с проверкой против записанной
метрики качества; это не отдельно сохранённый файл модели.
Большое число кандидатов значительно удорожает трассировку, поэтому
супервизор запускает **только один** расчёт одновременно и пишет состояния
в `study_runs.json`. После завершения матрицы `finalize.py` формирует
`results.md` с итоговой таблицей, а `report.py` — подробные метрики.
Первые три завершённых прогона слоистой модели (98 станций, 400 событий)
после **четырёх** обновлений дали RMS скорости 127.748 / 127.593 /
127.478 м/с для `top_n=1 / 5 / 10`, `d=1`, ошибки модели 0.2 с.
Медианная ошибка апостериорного среднего положения после двух обновлений —
2.690 / 2.679 / 2.664 км. При `top_n=5 / 10` медианное эффективное число
гипотез ≈4.8 / 9.0, но **ни у одного из 400 событий** нет массы более
10 км от MAP: это польза *локальной* смеси, а не подтверждение дальних
отдельных мод. После четырёх обновлений абсолютная RMS выше, чем после
двух-трёх: при оценке надо сравнивать как фиксированное число итераций,
так и оптимальную остановку, не подгоняя её по истине реальных данных. До завершения всех runs, особенно второй истинной
модели и редкой сети, нельзя делать вывод об универсальном выигрыше.
Условная масса `top_n` сама по себе не проверяет, что истинный гипоцентр
попал в отобранный набор.

### Подбор параметров для волнистых слоёв и шести баблов

Для эксперимента `layered6bubbles_240x120x120_98st_1200ev_grid20x10x6_minz30_noise01_pick005_seed42`
сохранён исходный полный run (`subdivision=9`, 1200 событий, `top_n=1`,
`λ=0.05`, `coverage_damping_power=1.5`, предел шага скорости 0.005,
12 циклов). RMS скорости относительно истинной модели в центрах 3456
инверсионных ячеек: 129.18 м/с в начальной модели; минимум 128.47 м/с
после **одного** обновления; 143.15 м/с после 11 обновлений. В 570 ячейках
внутри шести сфер RMS, напротив, снижается с 183.80 до 168.92 м/с, тогда
как вне сфер растёт с 115.37 до 137.49 м/с. Минимум обучающей процентной
невязки — после четырёх обновлений. Поэтому больше итераций без изменения
остановки/регуляризации не обещает лучшую модель: восстановление баблов
конкурирует с ложными изменениями вне них.

Для поиска причин есть диагностический поднабор **192 из тех же 1200 событий**:
`diagnostic_layered6bubbles_192ev_seed42`; времена прихода и скоростная
модель не пересчитывались. Первый этап изолированно меняет предел шага,
`λ` и `coverage_damping_power` при фиксированных `top_n=1`, `subdivision=4`,
без сглаживания, 12 циклов (прогоны и команды: локальный
`runs/layered_parameter_study_20260930/stage1.json`). При исходных настройках
минимальная ошибка внутри сфер 179.78 м/с после двух обновлений, но полная
ошибка уже 131.49 м/с против 129.18 м/с в начальной модели. Увеличение
предела шага до 0.015/0.03 с прежней регуляризацией резко ухудшает
восстановление. При шаге 0.015, `λ=0.5`, `coverage_damping_power=3` после
одного обновления полная RMS 128.36 м/с, внутри сфер 175.60 м/с; после
двух — 131.80/173.55 м/с. Это **предварительная диагностика**, а не
рекомендация для полного набора: поднабор хуже покрывает глубины, и результаты
при `subdivision=4` нельзя переносить на `subdivision=9` без проверки.
Истина здесь используется только при *оценке* сохранённых моделей и выборе
параметров, не в самой инверсии; итоговый вывод требует отложенной проверки
или отдельного полного запуска.

Для воспроизведения последующего сравнения точности и весов см. локальные
скрипты и статусы `runs/layered_parameter_study_20260930/stage1_fine.py`,
`stage1_fine.json`, `stage2.py`, `stage2.json`, `weight_report.py`. Второй этап
последователен: он ждёт завершения первого, фиксирует конфигурацию по минимуму
`RMS_всё + 0.25 × RMS_в_сферах` после одного/двух обновлений и затем меняет
**только** число, расстояние и температуру весов при общих четырёх циклах.
При `subdivision=9` (те же 192 события, пять циклов, 12 workers) исходная
регуляризация дала после двух обновлений RMS **131.65/179.83/119.87 м/с**
(весь объём / сферы / вне сфер). Усиленная (`λ=0.5`, coverage power `3`,
предел 0.005) дала **128.26/176.28/116.45 м/с**; тот же демпфинг при
пределе 0.015 дал **130.03/171.21/120.25 м/с**. Последний вариант сильнее
восстанавливает сферы ценой артефактов снаружи и хуже по выбранному общему
критерию. Победитель — `λ=0.5`, coverage power `3`, предел **0.005** после
двух обновлений; ещё циклы улучшают сферы, но портят общий RMS.

На втором этапе (та же подвыборка, `subdivision=9`, четыре цикла, фиксированы
все настройки кроме весов) после двух обновлений получены значения:

| `top_n`, `min_distance`, `temperature` | RMS вся модель / сферы, м/с | Среднее эффективное число весов на событие, первый цикл |
| --- | ---: | ---: |
| 1, 1, 1 | 128.26 / 176.28 | 1.00 |
| 2, 1, 1 | 128.21 / 176.08 | 1.65 |
| 3, 1, 1 | 128.24 / 176.16 | 2.32 |
| 3, 3, 1 | 128.24 / 175.97 | 2.36 |
| 3, 1, 0.5 | 128.26 / 176.19 | 1.88 |
| 3, 1, 2 | 128.22 / 176.10 | 2.72 |

Эффективное число = `1 / sum(weight²)` по кандидатам каждого события;
следовательно, эффекта «все дополнительные веса нулевые» здесь **нет**.
Однако разница восстановления по весам очень мала (порядка 0.05 м/с по
объёму между `top_n=1` и `2`) при большей стоимости трассировки: нельзя
называть увеличение `top_n` надёжным улучшением без полной проверки.
Изолированные сравнения температуры и расстояния выполнялись при `top_n=3`.
Полный отчёт со всеми итерациями и распределением весов — локальный
`runs/layered_parameter_study_20260930/weight_report.json`.

Все результаты выше — подвыборка, а не подтверждение на всех 1200 событиях.
Полные контрольные прогоны `top_n=1` и `2` с выбранной регуляризацией
сохраняются в `runs/layered_parameter_study_20260930/full_confirmation.json`
(одинаковые `subdivision=9`, пять циклов, 24 workers). Первый полный
контрольный run (`top_n=1`) уже завершился: RMS по всему объёму после
0/1/2/3/4 обновлений = 129.18/127.61/126.82/126.33/126.04 м/с;
в сферах = 183.80/178.85/174.64/170.89/167.77 м/с; вне сфер после
четырёх обновлений 116.03 м/с. Для сравнения в старом полном run после
четырёх обновлений — 132.05/173.82/122.12 м/с (весь объём / сферы /
вне сфер). Это подтверждает выигрыш усиленного демпфирования на полном
наборе, но **не** доказывает, что четыре обновления — оптимальная точка
остановки: последний сохранённый RMS продолжает снижаться. Парный полный run `top_n=2` после четырёх обновлений дал **126.05/167.78/
116.05 м/с** против 126.04/167.77/116.03 для `top_n=1`: существенного
выигрыша от двух весов на полном наборе **нет**. Выполнение заняло примерно
45 минут против 38 минут для `top_n=1` при пяти циклах; стоимость зависит
от машины и конфигурации. Результаты всех циклов обоих полных runs:
`runs/layered_parameter_study_20260930/full_report.json`.

Важно: **в перечисленных выше старых runs** масштабом softmax была
медиана **положительных различий между отобранными кандидатами одного
события**. Для ровно двух кандидатов с различными невязками эта медиана
равна единственной разнице, поэтому при `temperature=1` их веса всегда
`1/(1+e⁻¹) ≈ 0.731` и `0.269`, **независимо от величины разницы**. В
полном run среднее эффективное число весов на событие — 1.648 (1200 событий);
это не калиброванная вероятность гипоцентра. У трёх кандидатов веса
различаются по событию, но масштаб также относительный. Поэтому отсутствие
выигрыша от `top_n=2` нельзя понимать как свидетельство, что второй
кандидат имеет верную статистическую вероятность; для такой задачи надо
отдельно менять шкалу весов и заново проверять модель. Новая формула выше
устраняет эту константу, но приведённые RMS относятся **только к старой**;
выигрыш в качестве инверсии после изменения весов ещё не измерялся.

Проверка гипотезы о недостатке циклов: отдельный **полный** run с теми же
параметрами и `top_n=1`, но **10 циклами**
(`runs/layered_parameter_study_20260930/long_confirmation.json`) дал
RMS по всему объёму 126.04 после 4 обновлений, 125.82 после 5 и **125.27
м/с после 9** (в сферах 167.77 → 165.14 → **158.11**, вне сфер 116.03 →
116.50 → **117.70**). Обучающая невязка продолжила снижаться до 2.073%
после десятого обновления, но модель после него не сохранена: `iter_9`
соответствует **девяти** обновлениям. Для исходного слабого демпфирования
продолжение циклов портило общий RMS; **с усиленным демпфированием**
дополнительные циклы здесь полезны. Вне сфер ошибка постепенно растёт,
поэтому нельзя бесконечно продолжать прогон и нельзя переносить точное
число циклов на другие данные без проверки.

Истинные координаты событий не передаются инверсии. Сохранённые
`iter_i/model.npy` — модель
**после i обновлений**; строка `quality.jsonl` с `iter=i` соответствует
**после i+1 обновлений**.

### Регуляризация и диагностика checkerboard

`--smoothness-reg` (по умолчанию `0`, то есть выключен) штрафует разности
**обновлений медленности** соседних по грани инверсионных ячеек, а не сглаживает
истинную или начальную модель. Вес каждого ребра относительно среднего
диагонального элемента матрицы чувствительности — `smoothness_reg / 6`.
Параметр сохраняется в `meta.json` run. Для шумового эксперимента с глубиной
событий от 30 км можно попробовать, например, `--smoothness-reg 1.0` при
неизменных прочих настройках, но это пока **диагностическая гипотеза**, не
рекомендация для полного расчёта.

В дешёвой диагностике использованы первые 128 из 1000 событий сохранённого
зашумлённого эксперимента (приходы не пересчитывались), одинаковая
инверсионная сетка `(24, 12, 12)` и `--subdivision 4`. При `λ=0.05`,
`coverage_damping_power=1.5` модель, сохранённая **после пяти обновлений**
(`iter_5/model.npy` шестицклового запуска), дала RMS ошибки скорости
относительно известной истины 226 м/с по всему объёму и 179 м/с в верхних
0–30 км без сглаживания, против 219 и 164 м/с при `smoothness_reg=0.3`.
При `smoothness_reg=1` и 12 циклах лучшая сохранённая модель (после 8 циклов)
дала ≈206 и ≈118 м/с соответственно; последующие циклы ухудшали результат.
Это подбор по **известной синтетической истине** на поднаборе, а не независимая
оценка на всех 1000 событиях или на `subdivision 8`. У старого полного run
верхние 0–30 км были лучше примерно после 10, а не 14 циклов. Нижние
90–120 км практически не восстанавливают контраст даже при усилении
диагонального демпфирования: поверхностные станции и относительные приходы
слабо ограничивают эту часть области; один лишь подбор регуляризации не
гарантирует её восстановления.

В отдельном сравнении без сглаживания на тех же 128 событиях и шести циклах
`weights_top_n=2` и `3` почти не изменили результат относительно `1`:
RMS верхних 0–30 км сохранённой модели после пяти обновлений составила
≈179.5, ≈179.4 и ≈178.9 м/с соответственно. Так как число трассировок
увеличивается, для полного теста оставили `weights_top_n=1`.
`--weights-min-distance` задаёт минимальное расстояние между кандидатами по
Чебышёву **в индексах мелкой расчётной сетки**, не в километрах. Описанные
результаты относятся к **старой формуле**: тогда `--temperature` управляла
относительной мягкостью весов по разнице уточнённых невязок, и веса не были
калиброванными вероятностями. Новая формула и её ограничения описаны выше.
При `top_n=1` ни расстояние, ни температура не меняют результат.

Возможный источник систематики — несоответствие численной прямой/обратной
кинематики: инверсия привязывает станцию к центру мелкой FMM-ячейки, тогда как
прямая задача использует точные координаты. Для выборки 14 станций и всех
1000 истинных событий RMS разницы центрированных по событию времен между
PyKonal и SKFMM составлял ≈0.236 с при `subdivision 2`, ≈0.092 с при 4 и
≈0.071 с при 8. Это измерение *не доказывает*, что именно такая ошибка
вызывает верхние артефакты. Для выбора числа циклов без подглядывания в
истину понадобится отложенная проверка по событиям.
`run_name` содержит ID исходного эксперимента. Результаты инверсии сохраняются
в привычном `runs/`. Новый viewer показывает только runs с подтверждённой
связью с исходным экспериментом (ID и SHA-256 модели); старые runs без этой
связи не выводятся.

### Откуда берутся данные

- `output/<ID>/arrivals.csv`: наблюдения в секундах. Наблюдения привязываются
  к `event_id` и `station_id`, а не к порядку строк CSV. Пропущенные,
  дублированные и неизвестные пары вызывают ошибку. Для каждого события
  первое время должно быть нулём.
- `input/<ID>/stations.csv`: **точные** координаты станций в метрах; порядок
  станций согласован со столбцами матрицы `(events, stations)`. EMTomo на этапе
  внутреннего FMM по-прежнему переводит станцию в индекс расчётной ячейки;
  исходные координаты в адаптере не округляются.
- `input/<ID>/model.npz`: размеры области и истинная скоростная модель. Истина
  используется **только для метрик качества и отображения эталона в viewer**;
  начальная модель инверсии однородная. `true_model.npy` старого формата не
  считается оригиналом: viewer берёт непосредственно `input/<ID>/model.npz`.
- `input/<ID>/events.csv`: ID определяют порядок строк матрицы. Координаты
  истинных событий **не передаются** в восстановление и в сохранённые метаданные run.
  Viewer отдельно загружает их для маркеров, перехода `True Y` и `Hypo Distance`,
  проверяя хеши входов по `output/<ID>/metadata.json`. Порядок событий — порядок
  строк входного CSV, как при подготовке инверсии.
- `output/<ID>/metadata.json`: проверяются единицы SI, относительное начало
  отсчёта и SHA-256 всех файлов входа (включая `generation.json`, если он есть).
  Поддерживается пока только начало модели `(0, 0, 0)` в локальных метрических
  координатах. Данные не должны меняться между решением прямой и обратной задач.

### Viewer

```sh
python projects/EMTomo/server.py  # из корня проекта
```

Или из `projects/EMTomo`: `python server.py`. Если runs и данные находятся
не в стандартных каталогах, передайте `--runs-dir` и `--experiments-root`.
Откройте `http://localhost:5050` (Plotly загружается через CDN; для него нужен
доступ браузера к сети).

Левая панель — модель инверсии выбранной итерации, правая — исходные скоростные
блоки из независимого forward input. Обе оси X/Z и общий Y задаются в **км**;
границы скоростной сетки нанесены на оба среза; для плотных исходных сеток
overlay показывает только часть точных границ (не более 16 на ось), а подписи
осей подбираются автоматически (около шести делений) независимо от шага
скоростных ячеек. Шаг перемещения по Y
по умолчанию — 1/10 протяжённости области по Y, его можно поменять в поле
`Step` (км). Для скоростей шкала цветов общая и не переключается; Δs имеет
отдельную симметричную шкалу, так как измеряется в других единицах. Разрешение
среза инверсии повышено до 8× по каждой пространственной оси (не более 240
образцов на ось), при этом backend отдаёт только двумерный срез и ограничивает
размер ответа. Истина остаётся **на своей исходной крупной сетке**, без
интерполяции к сетке инверсии. Старые runs viewer намеренно не поддерживает.

События отображаются в точных координатах: прозрачность плавно уменьшается
с расстоянием до среза Y (характерный масштаб — 1/10 ширины области), независимо
от размера ячеек и шага ползунка. Подпись получает выбранное событие; остальные
ID доступны при наведении, чтобы тысяча подписей не закрывала модель.

`Hypo Weights` сохраняет мелкую FMM-сетку. Его `Y layer` — индекс слоя с шагом 1;
рядом отображается координата центра слоя в км. Кнопка `True Y` переходит в слой,
содержащий истинное положение выбранного события. Шаг скоростных панелей на
эту навигацию не влияет. `Hypo Distance` показывает расстояние в метрах от
гипотезы с наибольшим весом до истинного события. Для ещё не записанных гипотез
текущей итерации данных пока нет.

Docker-viewer монтирует `runs`, `experiments/input` и `experiments/output`
только для чтения. Из output для отображения требуется лишь `metadata.json`;
матрица приходов и зависимости прямого решателя viewer не нужны.

Проверки кода:

```sh
python -m pytest projects/EMTomo/tests -q
python -m pytest projects/forward_modeling/tests -q
```

Старые скрипты checkerboard/geysers вызывают `main(config)` без ID и пока
сохраняют прежний путь генерации для обратной совместимости. Основной CLI
`main.py <EXPERIMENT_ID>` использует **только** заранее рассчитанные наблюдения.
Их автоматическую генерацию при запуске томографии намеренно не добавляли.
