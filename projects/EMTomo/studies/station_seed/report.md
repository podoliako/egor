# Околостанционная затравка EMTomo: исправление и контроли

## Краткий итог

1. Правка `c381cfd` от 2026-10-13 уже правильно относит внутренний участок
   станционной сферы к станционной ячейке. Её не отменяли.
2. В `eikonal.py` исправлен другой локальный дефект: внутренняя среда становится
   однородной **до** вызова FMM, а не только посредством перезаписи возвращённых
   времён. Входная модель не изменяется, скорости снаружи сферы сохраняются.
3. Этот дефект **не объясняет основные артефакты flat4**: полный парный контроль
   `fixed-c500` на 12 циклах не показал улучшения реконструкции.
4. Найдена отдельная проблема численной непрерывности `scikit-fmm 2025.06.23`,
   `order=2`: изменение Vp на один ULP вызывает миллисекундные скачки времени.
   Она воспроизводится без инверсии и даже без сферической затравки.
5. Независимые однородные контроли создают ложную структуру без шума и без
   релокации. Поэтому численные эффекты нельзя списать только на шум пиков.

**Не меняли:** регуляризацию/сглаживание, начальную модель, ограничение шага,
число циклов метода, алгоритм релокации, радиус сферы, порядок FMM, зависимости.
Prior к начальной модели не добавляли. Критерии остановки не разрабатывали.

## 1. Фактическая версия и локальное исправление

Основа — HEAD `c381cfdde24bf291fd7fd565f69681fa1867324f`, не описание из README.
Четыре исходных flat4-запуска начались 2026-10-13 20:01:19 UTC, после коммита
`c381cfd` в 18:53:37 UTC. Git SHA в исходных метаданных запусков не записан;
проверка воспроизведения ниже сильнее одного сопоставления времён коммитов.

Сохраняется однородная сфера радиуса `3h = 375 м` со скоростью станционной
ячейки. Старая формула:

```python
T = skfmm.travel_time(distance - R, original_velocity, order=2) + R / v_station
T[inside] = distance[inside] / v_station
```

Инициализация FMM использует обе стороны нулевого фронта. Поэтому последняя
строка не удаляет уже распространившееся влияние исходной внутренней скорости.
Теперь для marching используется копия массива с `velocity[inside] = v_station`.
Это согласует локальную среду с заявленной затравкой и предыдущей правкой `G`.
Оно **не превращает** ray Jacobian в точную производную дискретного FMM.

Метка `run_params.travel_times` в новых запусках —
`skfmm_order2_exact_station_homogeneous_sphere_v2`, чтобы отличать их от старых.
На однородной среде возвращаемое поле не изменилось.

### Изолированный контроль утечки

Сетка `(32,24,24)`, `h=125 м`, фон `4000 м/с`, станция `(1900,1450,0)`.
Только оболочка `250 < distance <= 375 м` замедляется до `2000 м/с`;
станционная ячейка и внешняя среда остаются прежними.

| Изменение времён далее 750 м | До правки | После правки |
|---|---:|---:|
| RMS, мс | 0.9153 | **0** |
| min/max, мс | −0.571 / +3.772 | **0 / 0** |

Внутри сферы возвращаемые времена совпадали и раньше. То есть проблема была
не в аналитической перезаписи, а в зависимости внешнего marching от среды,
которую параметризация затравки объявляет однородной.

Регрессионные тесты дополнительно проверяют поверхность, внутренний источник,
углы домена, две скорости оболочки, read-only вход, сохранение наружной
неоднородности и сферу, полностью покрывающую маленький домен.
До правки: **9 failed, 2 passed**. После правки эти **11 тестов проходят**.

## 2. Насколько это влияет на сохранённые flat4-модели

Каждое сравнение использует **все 52 станции и 1920 истинных событий**.
Из разности времён вычитается среднее по станциям отдельно для каждого события.
Это невзвешенное центрирование для диагностики; не полная likelihood инверсии.

| Сохранённая модель | Centered RMS изменения времени, мс | Максимум абсолютного centered изменения, мс |
|---|---:|---:|
| initial, c500 | **0** | **0** |
| initial, c1000 | **0** | **0** |
| final, fixed-c500 | 0.1313 | 1.9787 |
| final, hard-c500 | 0.1387 | 2.3202 |
| final, fixed-c1000 | 0.0642 | 1.1262 |
| final, hard-c1000 | 0.0821 | 1.4977 |

В исходном верхнем слое внутри сферы ещё нет латерального контраста, поэтому
стартовые поля совпадают точно. В финальных моделях эффект ненулевой, но RMS
значительно меньше масштаба шумов исходных данных. Максимумы не являются RMS.

### Полный парный контроль fixed-c500

Один и тот же исходный эксперимент
`flat4_20x7x7km_52st_1920ev_grid24x8x10_z0.5-5.5_noise01_pick001`:

- все 1920 событий и 52 станции, гипоцентры истинные и фиксированные;
- coarse cell 500 м, subdivision 4, fine cell 125 м, `nearest`;
- 12 циклов, lambda 0.5, coverage power 1, предел шага ±2%;
- sigma relative 0.01, absolute 0.01 с, model 0.02 с;
- 12 workers; ray deposition и обновление модели одинаковые;
- различие только в передаваемой FMM внутренней скорости сферы;
- baseline — сохранённый полный запуск; **первые два baseline-цикла повторены
  заново: модели и delta_s совпали с сохранёнными побитово**.

| Итоговая метрика | Baseline | Исправленная затравка |
|---|---:|---:|
| RMS ошибки всей модели, м/с | 159.3666 | 159.4786 |
| RMS ошибки верхних 500 м, м/с | 94.9402 | 95.7410 |
| Латеральная RMS верхних 500 м, м/с | 88.9549 | 89.8542 |
| RMS ошибки станционных ячеек, м/с | 94.2840 | 96.4419 |
| Centered RMS невязки со своим forward, мс | 21.2325 | 21.2314 |

Исправленный запуск занял 431.5 с. Отказов лучей **0 из 1 198 080**.
RMS разницы финальных моделей — 10.95 м/с, максимум 163.72 м/с, причём максимум
не в верхнем слое. Это не оценка улучшения: истинная ошибка почти прежняя.

**Вывод:** исправление устраняет локальный дефект, но считать его средством
устранения верхних артефактов по этому контролю нельзя.

## 3. Finite-difference контроль чувствительностей

Для стартовой `c500` проверены станции 0, 24 и 51; для каждой — станционная
ячейка, четыре горизонтальных соседа и ячейка под ней. Каждый столбец проверен
на всех 1920 событиях. Central differences использовали относительные изменения
медленности ±0.001 и ±0.003, для обеих формул затравки.

Для station 0 и её симметричного аналога station 51 при fraction 0.003:

- относительная L2 ошибка станционного столбца `G` после исправления — около 5.4%;
- у двух соседних столбцов с заметной чувствительностью — около 24% и 18%;
- исправление внутренней среды не устраняет эти различия.

У станции 24 расхождения намного больше и finite differences неустойчивы к
размеру возмущения. Нельзя интерпретировать их как надёжную истинную производную
и механически заменить ими `G`: дальнейший контроль выявил скачки самого FMM.
Это raw travel-time derivatives, не производная полной profiled likelihood.

## 4. Отдельная проблема непрерывности scikit-fmm order=2

Среда выполнения контролей: Python 3.12.3, NumPy 2.4.0,
`scikit-fmm 2025.06.23`.

### 3D-пример

- сетка `(48,32,32)`, `h=125 м`, станция `(1000,875,0)`;
- Vp везде 4000 м/с;
- только блок `[4:8,4:8,:4]` меняется на `nextafter(4000, +inf)`;
- внутренняя сфера в обеих средах принудительно остаётся одинаковой;
- максимальное изменение Vp: **4.5474735e-13 м/с**.

| Порядок FMM | Максимум изменения времени, с | RMS изменения времени, с |
|---|---:|---:|
| 1 | 7.51e-14 | 1.12e-14 |
| 2 | **1.7434e-3** | **1.3734e-4** |

Это видно уже в float64 выходе `skfmm`, до добавления `R/v_station`, перезаписи
внутренности и преобразования в float32. В production field максимум также
1.7434 мс. Следовательно, float32 хранение и ray rasterizer не объясняют скачок.

### Независимый 2D-пример, вообще без сферы

`phi=1` на сетке `(24,24)`, только четыре узла `[7:9,7:9]` имеют `phi=0`.
Отрицательной области нет. Скорость 4000 м/с; блок `[4:8,4:8]` меняется на один ULP.

| Порядок FMM | Максимум изменения времени, с |
|---|---:|
| 1 | 8.88e-16 |
| 2 | **7.7748e-3** |

Тем самым проблема не специфична к поверхностной полусфере и не требует
распространения внутри сферы.

Исследование second-order stencil указывает на переключение допустимости второго
upwind-соседа при почти равных временах. В исходном 3D-примере при вычислении
`(6,4,2)` время первого x-соседа меняется с `0.020583727972626437` на
`0.020583727972626434 с`, тогда как время второго равно
`0.020583727972626437 с`. Точное условие `T2 <= T1` меняет ветку. Изменение времени
порядка 3e-18 с превращается в конечное изменение коэффициентов stencil.
См. `travel_time_marcher.cpp`, `updatePointOrderTwo`, версия 2025.06.23.
Это не доказательство повреждения heap; такой гипотезы для воспроизведения не нужно.

Простые экспериментальные допуски в сравнении и группировке heap не устранили
скачок полностью. Они **не внесены** в установленную библиотеку или production.
Не внесены также округление модели, подавление малых обновлений и переключение
FMM на первый порядок: они скрывали бы проблему или меняли точность всей задачи.

В тестах есть **strict xfail** на ожидаемую физическую непрерывность production
field. Это явная известная нерешённая проблема, не пройденный тест. Если поведение
библиотеки будет исправлено, XPASS потребует снять/пересмотреть отметку.

## 5. Однородные инверсионные контроли

Небольшая отдельная геометрия: 6×4×4 км, 768 неизвестных, 12 поверхностных
станций, 160 событий, fine cell 125 м. Истина и старт **4000 м/с везде**.
Истинные гипоцентры фиксированы. Шум не добавляется. Обе ветви используют
одинаковые lambda 0.5, coverage 1, шаг ±2% и **12 циклов**.

### A. Самосогласованные времена того же решателя

Наблюдения рассчитаны тем же baseline FMM из истинной стартовой модели.

- После первого цикла RMS изменения Vp — **2.82e-13 м/с**: численный ноль.
- После второго — **1.31 м/с** по модели, **3.38 м/с** в верхнем слое,
  локально до +23.83 м/с.
- После 12 циклов RMS верхнего слоя: baseline **10.55 м/с**,
  исправленная затравка **9.65 м/с**.

То есть машинно малое первое обновление нарушает самосогласованность forward.
Это провал null-контроля, а не шум измерений или ошибка гипоцентров. Его связь
с FMM дополнительно подтверждается прямыми примерами раздела 4.

### B. Независимые точные времена distance/4000

Времена рассчитаны аналитически, не другим численным решателем. Начальная
невязка EMTomo после центрирования имеет RMS **1.6836 мс**.

| После 12 циклов | Baseline | Исправленная затравка |
|---|---:|---:|
| RMS ошибки модели, м/с | 19.23 | 19.27 |
| RMS ошибки верхнего слоя, м/с | 37.54 | 37.57 |
| Диапазон ошибок верхнего слоя, м/с | −70.71…+105.01 | −72.29…+105.48 |
| Centered RMS невязки, мс | 0.9540 | 0.9478 |

Инверсия превращает чисто численное расхождение forward с аналитикой в ложную
скоростную структуру. Исправление утечки это почти не меняет.

**Ограничение вывода:** этот контроль доказывает существование механизма, но не
измеряет его долю в больших ошибках flat4. Он не отделяет все погрешности
сферической затравки, дискретного marching, интерполяции и приближённого `G`.
Называть все 95 м/с ошибки верхнего слоя flat4 следствием найденного скачка нельзя.

## 6. Решение по текущей работе

- Оставить узкую проверенную правку внутренней среды и её regression tests.
- Не переписывать снова распределение внутренней длины луча: прежняя правка
  была правильной для сохраняемой однородной сферы.
- Не менять радиус/порядок по одной картинке и не считать верх исправленным.
- Отдельный следующий численный вопрос — устойчивый second-order forward:
  проверка исправленного/альтернативного solver на этих же continuity и null
  контролях **до** новой полной инверсии. Простого проверенного исправления
  поведения `skfmm order=2` в этой работе не получено.
