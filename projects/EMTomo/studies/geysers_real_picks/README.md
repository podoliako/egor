# Реальные P-пики для используемых событий Гейзеров

Скачано 28 октября 2026 года для **точно тех же 3776 event ID**, что в elevated-геометрии экспериментов 1–20 апреля 2011. Станции не ограничивались исходными 26.

## Результат

- Все **3776/3776 событий найдены**, у всех есть P-пики.
- **49158 P-пиков**, 31 станция BG, 49158 уникальных пар event/network/station; неоднозначных пар и точных дубликатов нет.
- На исходных 26 станциях: **42920** P-пиков.
- На остальных пяти — **AL1, AL2, AL6, HBW, HER**: **6238** P-пиков.
- На событие: минимум 2, медиана 11, среднее 13,02, максимум 31 P-пик.
- Никакие пики не отбрасывались по кодам качества. Исходные weight codes 5/7 сохранены; их нельзя автоматически интерпретировать как стандартные Hypoinverse-коды 0–4 или как σ времени.
- Для события **3156432** два пика раньше каталогового origin: STY на 0,13 с и NEG на 0,01 с. Они не удалены и не исправлены. Требуется проверка перед инверсией; каталоговый origin не является точным временем очага.
- Времена origin в скачанном архиве и исходной геометрии различаются не более чем на 0,01 с.

## Источник

Официальный EGS/BG-каталог NCEDC: <https://ncedc.org/egs/catalog-search.html>.
POST <https://ncedc.org/cgi-bin/catalog-search2.pl>, формат `egsphraw` (Hypoinverse summary and phases), дневные запросы за 1–20 апреля 2011. Это тот же EGS-каталог, что использован для геометрии. FDSN-сервис `service.ncedc.org` во время массового скачивания был недоступен; официальный legacy-интерфейс работал. Для первого события 3156099 P-времена RGP и SB4 и число P-пиков совпадают с ранее проверенным QuakeML.

«Все станции» здесь означает все станции, представленные в фазовых записях выбранных EGS-событий. Не выполняется отдельный поиск совпадений с событиями других каталогов или автоматическая расстановка новых пиков по волновым записям.

Данные: `projects/EMTomo/data/geysers_2011/real_picks/`:
- `raw/2011-04-*.html` — 20 оригинальных ответов сервиса. В них сохранены также S-фазы и попавшие в дневной запрос события вне нашей выборки.
- `P_picks.csv` — все P-пики только нашей выборки: event ID, UTC origin/pick, network/station/location/channel, phase, onset, polarity, исходный weight code, секунды от каталогового origin и от первого P-пика, признак исходных 26 станций, исходный файл и номер строки внутри PRE.
- `event_coverage.csv` — покрытие для каждого из всех 3776 событий.
- `station_coverage.csv` — покрытие по каждой станции.
- `summary.json` — статистика, параметры запросов, исходные SHA-256 геометрии и SHA-256 всех raw-ответов.
- `status.json` — состояние скачивания/сборки таблиц.

Фазы выбраны по фиксированным колонкам Hypoinverse; implied centiseconds преобразованы в UTC с корректным переносом минут/суток. Origin ID берётся из колонок 137–146, завершение каждого события проверяется. Синтетические наблюдения не подменялись. На этапе скачивания координаты пяти дополнительных станций не готовились. Теперь все 31 станции проверены и включены в подготовленный эксперимент ниже.

## Проверка спрятанных 10% приходов

Выполнена `evaluate_holdout.py`; результаты — `runs/geysers_real_20261031_pick01/holdout_evaluation_v2/`. Все **4775 holdout-пиков 3186 событий** оценены, без исключений. В train остаются 42973 пика 3471 события. Для четырёх фиксированных моделей (начальная, hard после 21 успешного обновления, soft после 24, tomoDD после 3) независимо построены поля одним frozen skfmm-оператором на 125-м сетке. Native tomoDD nodal Vp интерполирован в истинных lon/lat/sea-level depth на общий физический объём 23×11×7 км.

Для каждого события местоположение заново найдено **только по TRAIN**: global grid likelihood, 128 уточняемых кандидатов с dmin2, MAP. Время очага относительно первого TRAIN-пика — взвешенное среднее TRAIN-остатков с дисперсией `(0.01*T_predicted)^2 + .02^2`. Каталожные позиции/origin и сохранённые предфинальные E-шаги при оценке не используются. Эти offsets и прогнозы всех 31 станций сохранены ДО открытия holdout в `*_predictions.npz`, их хеши/параметры/хеши исходных моделей — в `*_fit.json`. На holdout ни позиция, ни origin не подгоняются. Метрика — детерминированный MAP-прогноз для всех моделей, не полная posterior predictive смесь soft.

| Модель | Train RMSE, мс | Holdout RMSE, мс | Holdout MAE, мс | P90 абсолютной ошибки, мс |
|---|---:|---:|---:|---:|
| Начальная 1-D | 65,97 | 105,30 | 66,18 | 149,53 |
| EMTomo hard, 21 обновление | 54,35 | 95,92 | 55,74 | 131,55 |
| EMTomo soft, 24 обновления | 54,26 | 98,61 | 56,30 | 132,31 |
| tomoDD, 3 обновления | 56,84 | 94,16 | 56,12 | 132,87 |

Это проверка **скоростных моделей общим оператором и общей train-localization**, а не end-to-end native tomoDD residual score. У tomoDD исходный run удержал 3467/3471 событий, но общий evaluator предсказывает все 4775 holdout-пиков, локализуя и остальные события по их train-пикам. У hard нет финальной 24-итерационной модели: использован последний корректный checkpoint после 21-го обновления, сверенный с сохранённой моделью начала следующей итерации.

Обнаружена известная численная ошибка Powell `zero-size array ... maximum ... no identity`: в evaluator для неё добавлен одинаковый для всех моделей резервный bounded coordinate descent в той же мелкой ячейке, только по TRAIN. Он понадобился ровно для **одного кандидата одного события hard**; initial/soft/tomoDD — 0. Ошибки других типов не подавляются. Скоростные модели и frozen inversion runtime не менялись. Первый незавершённый evaluator v1 сохранён отдельно для аудита; законченная проверка — **v2**.

`summary.json`/`report.md` содержат метрики, `holdout_predictions.csv` — наблюдение/прогноз/остаток каждой пары для всех моделей, `holdout_absolute_error_ecdf.png` — ECDF. Дополнительно `paired_event_bootstrap.json`: 2000 парных bootstrap-перевыборок событий, seed20261101, pick-weighted RMSE. Для tomoDD−hard разница −1,76 мс, условный 95% интервал [−4,63; 0,75] мс; для soft−hard +2,69 мс, [0,51; 5,57] мс. Это условная оценка на одном split и фиксированных моделях, без ресэмплинга обучения и пространственных зависимостей между событиями.

**Ограничение слепоты:** tomoDD изначально использовал внешний каталог, потенциально уже зависящий от скрытых пиков. Общая relocalization не использует этот каталог, но не устраняет потенциальное косвенное влияние старта на полученную скорость. Поэтому это не строго слепая CV полного конвейера. ### Стартовая региональная модель

Выбрана **NCSN GEY**, официальная [таблица 8 NCEDC](https://ncedc.org/ftp/pub/doc/ncsn/shadow2000.txt). Исходный документ сохранён неизменённым в `data/geysers_2011/regional_model/shadow2000.txt`, SHA256 `b292262941f880fa8f5bc81114c4bc4a080a89b843b068f22b8e53ec53abaa23`.

| Исходная глубина, км | Vp, км/с |
|---:|---:|
| 0 | 4.10 |
| 3 | 5.47 |
| 8 | 5.75 |
| 20 | 6.02 |
| 22 | 7.90 |

Использован **линейный градиент Vp**, а не старый вариант постоянных слоёв из другой части той же таблицы. NCEDC ссылается на Eberhart-Phillips & Oppenheimer (JGR 1984), региональное описание — Oppenheimer et al., NCSN Bulletin 1992, USGS OFR 93-578.

Экспериментальная конвенция явно записана: исходный ноль модели отождествлён с нулём глубины каталога/уровнем моря; `z_local=d_source+1.166 км`. Выше исходного нуля скорость продолжена постоянной 4.10 км/с. **Эта привязка и продолжение — предположения подготовки, не установленное описание обработки EGS-каталога.** В скачанных заголовках код crust model пуст. Станционные поправки NCSN не заимствуются.

`methods/regional_model.json` хранит источник/конвенции; `methods/initial_velocity_m_s.npy` — общий старт EMTomo 23×11×7 с 1-км ячейками. Профиль в центрах локальных слоёв 0.5,…,6.5 км, м/с:
`4100, 4252.526667, 4709.193333, 5165.86, 5488.704, 5544.704, 5600.704`.

tomoDD получает те же значения на внутренних вертикальных узлах, но его нативная узловая интерполяция отличается от кусочно-постоянных ячеек EMTomo. Географическая сетка tomoDD охватывает повёрнутую область, а не использует искусственное географическое вложение старых synthetic-тестов.

### Настройки и native tomoDD

`methods/emtomo_configs.json`: soft `s16` / hard `h07`, 24 цикла, K128/top40/dmin2, λ1, coverage damping=0, шаг ±2%, subdivision8; soft T=4×4, 2×4, 1×16. Начальная модель заменена региональной, шум синтетических пиков **не перенесён**. Реальная неопределённость неизвестна: launcher требует явно выбрать σ перед выполнением. `weight_model_sigma_s=0.02` сохранён как отдельный параметр прежней конфигурации, не измеренная ошибка пиков.

`methods/tomodd/`: `phase.dat`, `event.dat`, `station.dat`, `absolute.dat`, `dt.ct`, `dt.cc`, `ph2dt.inp`, `MOD`, `grid.dat`, `tomoDD-SE.inp`, оба support-файла и manifest. Параметры `dd1-d40-s5`; **каталожные координаты без добавленного шума**. Исходные UTC сохранены; отрицательные интервалы относительно origin не обрезаются. Native reader принимает signed times. Коды качества не превращены в выдуманные σ; native-экспорт использует одинаковые веса 1.

Каждая строка DD построена только из двух train-пиков: 42973 абсолютных наблюдения, 54317 разностных наблюдений, 6925 пар событий, расстояние ≤3 км, степень ≤4. `dt.ct` хранит два времени, а не готовую разность. `ph2dt.inp` — формат для совместимости, **не запускайте ph2dt поверх этих файлов**: его выбор пар отличается.

Граф: одна компонента 3444 события, пять компонент по 5, два изолированных события **3157636, 3259971**. Изолированные сохранены в абсолютных данных. При будущей инверсии нужно проверить фактическое удержание событий native solver; Python-проверка не гарантирует этого. Требуется исправленный binary `runs/tomodd_guard_fix_20261027/build/tomoDD-SE`; его хеш сохранён. Сам native solver пока не запускался.

**Оговорка CV:** каталог для старта tomoDD уже получен внешней обработкой, потенциально с использованием будущих holdout-пиков. Прямой передачи этих наблюдений в absolute/DD нет, но это не строго слепая проверка полного конвейера с независимым каталогом. EMTomo каталога не получает — это согласованная пользователем асимметрия сравнения. При будущем CV время очага/позицию оцениваем по train в финальной модели; на holdout их не подгоняем.


По умолчанию это **только проверка**. Реальный запуск требует `--execute` и явного `--absolute-pick-sigma-s`; relative sigma по умолчанию 0. До выбора общей для hard/soft модели ошибок по train (без holdout) инверсии не запускаем. Для длительного запуска также нужно ограничить BLAS/OMP-потоки, как в прошлой очереди.

Sparse-поддержка распространяется на likelihood с интегрированным origin, shortlist/refinement, лучи, нормальные уравнения и диагностику. Полные таблицы сохраняют прежний быстрый batch-path. Пропуски не считаются failed rays; маски/индексы логов сохраняют глобальные station ID. Синтетический loader по-прежнему требует полную таблицу, а real-loader имеет отдельную строгую схему и не создаёт фиктивную truth.

Проверки: `tests/test_sparse_events.py`, `tests/test_real_experiment.py`, `studies/geysers_real_picks/test_{prepare,tomodd_inputs,finalize}.py`: эквивалентность явной station-подвыборке, dense/compact rays, multiprocessing, сохранение полного пути, отсутствие утечки holdout/каталога в EMTomo, native-DD пары только из train, одинаковые стартовые Vp на соответствующих узлах и запрет запуска без явной σ.
