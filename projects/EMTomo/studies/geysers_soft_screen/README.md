# Ночной скрининг soft на модели Гейзеров с разломом

**24 soft-конфигурации + 13 уникальных hard-контролей**, строго по одному расчёту за раз, 24 event workers на расчёт. Старые прогоны не изменяются. Данные синтетические; реальные скачанные пики не используются. **Новых прямых задач нет.**

Состояние: `runs/geysers_faulted_layers/soft_screen_20261028/`.
- `manifest.json`: точные 37 конфигураций, порядок, hard-control mapping, поднаборы станций, исходные SHA-256.
- `snapshot/`: отдельная копия ускоренного runtime, включая поддержку расписания температуры.
- `runner/`: зафиксированные скрипты worker/supervisor и рецепт подготовки.
- `status.json`: heartbeat каждые 5 с, текущий case, PID, completed/failed/pending.
- `queue.log`: запуски/завершения кейсов.
- `cases/<ID>/result.json` и `run.log`: статус, фактический run_dir, параметры, итоговый RMSE и лог инверсии.
- `summary.csv`: промежуточный и итоговый список результатов.
- Результаты инверсий — стандартные `runs/run_gfss28-<case>-...`, доступны viewer.

## Анализ завершённой серии

Все 37 прогонов завершились без ошибок. Все 13 точных hard-контролей уже были выполнены в ночной очереди; повторные hard не запускались. `analyze.py` проверяет метаданные/соответствие пар, исходные SHA-256, все complete markers, фактические расписания и пересчитывает ошибки из финальных моделей.

В каталоге состояния сохранены `analysis.md`, `analysis.csv`, `analysis.json` (все 24 пары), а также `hypocentre_metrics.json` (все 37 прогонов, все 3776 событий). Выигрышей soft по RMSE на 1-км оракле, мелкой истинной модели и в полосе разлома x=5–8 км — **0/24**; нет выигрышей и на промежуточных одинаковых по номеру итерациях. Самые близкие по парному RMSE: s05/h03, s14/h05, s09/h03, s01/h01. Лучший абсолютный soft s16 (24 цикла) также уступает своему 24-цикловому hard h07.

Для MAP-гипоцентров P90 улучшился только у s21/h10: 458,92/467,79 м (1,9%), но медиана и томография хуже. Это последний E-step до финального обновления скорости; одна реализация шума не позволяет утверждать устойчивое преимущество. Последние E-step всех 37 прогонов — без failed rays.

Анализ читает сохранённые модели и `hypocentre_metrics.json`; не запускает FMM/EM. Таблица содержит также RMSE относительно 125-м истины, полосу разлома и локальный глубокий скоростной контраст, чтобы увеличение амплитуды не подменяло общее качество.

## Общие параметры

Область 20×7×7 км; 3776 событий; истинная модель с вертикальным разломом x=6,5 км и тремя скоростными средами. Исходная чистая матрица — 3776×26 абсолютных времён ранее завершённой прямой задачи. Сетка инверсии 1 км, subdivision8/nearest; начальные слои 0,85/2,3 км, 3850/4550/5300 м/с. По умолчанию: 12 циклов, λ=1, coverage power=0, шаг ±2%, model sigma=20 мс, без шума. Solver=dense, batch8, compact rays, fast refinement. BLAS/OMP/MKL/Numba threads=1, workers=24 для всех сравниваемых расчётов.

K — уточняемый shortlist, N — сохраняемые гипотезы, d — Chebyshev dmin в 125-м ячейках ДО уточнения. Hard получает те же K/N/d и использует one-hot, soft — смесь. Размер модели/мощность шума не подбираются по истине.

Расписания:
- **A:** 4×4 итерации → 2×4 → 1×4.
- **B:** 8×3 → 4×3 → 2×3 → 1×3.
- **A24:** 4×4 → 2×4 → 1×16.

## Станции и шум

Жадный farthest-point от наиболее удалённой от центра станции по фактическим XY в метрах, без использования событий, приходов или истинной скорости. Поднаборы вложены; итоговый порядок сохраняет порядок исходных CSV:
- **8:** ACR, AL5, EPR, FNF, JKR, MNS, RGP, SB4.
- **12:** ACR, AL4, AL5, BRP, DRK, EPR, FNF, JKR, MNS, PFR, RGP, SB4.

Высоты/XYZ и все ID событий неизменны. Шум — существующий независимый Gaussian relative+absolute, pair-ID keyed PCG64, seed42: одинаковые случайные числа в общих парах для всех уровней/поднаборов. Шум добавлен к абсолютным чистым временам, ПОТОМ вычтен первый приход среди выбранных станций. Один seed — скрининг, не доказательство статистической устойчивости преимущества.

Производные датасеты размещены в стандартном `projects/forward_modeling/experiments/{input,output}/gfsoftscreen28_...`; исходный набор не изменён. Для каждого проверены ID/XYZ, формы, шум, нормализация и контрольные суммы; в metadata явно указано отсутствие нового forward solve.

## Запуск и восстановление

План уже подготовлен; `prepare.py` откажется его молча перезаписывать. Копирование численного snapshot выполняется явно до подготовки. Для fresh plan рецепт — `prepare.py`; выполненные команды и хеш runner сохранены в `launch.json` состояния.

Из `projects/EMTomo`, без инверсии:

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 NUMBA_NUM_THREADS=1 /mnt/disk01/egor/venv/bin/python3 -B studies/geysers_soft_screen/worker.py --state runs/geysers_faulted_layers/soft_screen_20261028 --case s08 --validate-only
```

Supervisor (уже запущен в отдельной сессии; не запускать вторую копию):

```sh
/mnt/disk01/egor/venv/bin/python3 -B runs/geysers_faulted_layers/soft_screen_20261028/runner/pipeline.py --state runs/geysers_faulted_layers/soft_screen_20261028
```

Очередь начинает с наиболее перспективных s03/s08/s19/s20/s23 и необходимых им контролей, затем заканчивает остальные варианты. Максимум один worker одновременно; лимит 4 часа на один расчёт, внешний предел supervisor — 48 часов. Ошибка/таймаут кейса сохраняются, очередь переходит к следующему. TERM/INT supervisor останавливает группу процессов активного worker. HUP игнорируется; stdin/stdout отделены от SSH/редактора.

Для resume запускать ту же frozen-команду только после проверки, что старый supervisor завершён: flock предотвращает дубликат. Готовые результаты с финальной моделью и всеми complete markers пропускаются. Failed/incomplete попытки не пересчитываются автоматически и старые run_dir не затираются; для их повторения потребуется отдельное решение.

Поддержка annealing обратно совместима: `InversionConfig.temperature_schedule` — None либо последовательность ровно n_cycles конечных положительных чисел; CLI `--temperature-schedule`. В meta хранится всё расписание, а в `iter_N/temperature.json` — фактическая T. Без расписания поведение прежнее.

Проверки: 213 pytest tests + 6 subtests прошли, включая расписание и mocked EM, план 24/13, вложенные станции, порядок noise→normalization без forward, последовательность/ошибки/lock/timeout очереди. Дополнительно dry-run s08, s16 и s23 на настоящих сохранённых данных.
